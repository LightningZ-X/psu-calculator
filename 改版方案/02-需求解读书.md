## 1. 逐条解读（含我的判断与验收标准）

### R1 — 「一眼 AI」的视觉必须根除

**你的意思**：当前配色（青绿 + 蓝 + 橙 + 紫）和元素风格（渐变 logo、emoji 图标、统一圆角卡片）是 AI 生成模板的典型特征，需要有人专门盯着改。

**我的翻译**：这不是「换个颜色」的问题，是**三条可检验的规则**：
1. 强调色收敛到**一种**（ROG 红 `#ff0033`），总面积 < 3%；
2. **删除全部渐变、发光、emoji**，图标改内联 SVG 描边风格；
3. **圆角收到 2px**，卡片形态多样化——数据用行式列表，设置用分隔线行，不要每块都套同一个面板。

**验收**：设计系统文档《01-设计系统-ROG奥创.md》第 4 节的三条铁律逐条自查通过；全站 grep 不到 emoji；grep 不到 `linear-gradient` 用于装饰（进度条除外）。

**依据**：真实奥创截图显示其强调色仅红色、圆角接近直角、分区靠亮度差而非描边。详见设计系统文档。

### R2 — 布局从「10 张卡全展开」改成「导航式分步」

**你的意思**：既然是 1→10 的流程，就不该一次性全铺开，应该上一步/下一步。

**我的翻译**：
- 左列改为**步骤容器**，同一时刻只显示 1 个步骤面板；
- 顶部（或左栏）放**横向步骤条**，可点击跳步，已完成步骤打勾；
- 底部固定 `上一步 / 下一步`，末步为 `生成报告`；
- 每步只放**该步的控件 + 一句话说明**，其余内容收纳进 tooltip；
- 保留一个**「跳过此步」**出口——工具类产品强流程会劝退老手。

**验收**：
- 1440×900 下首屏同时可见「步骤条 + 当前步控件 + 推荐瓦数」；
- 键盘 `Alt+←/→` 可切步，`Tab` 顺序正确；
- **打印时所有步骤强制展开**，导出的 PDF 与现在内容一致。

**风险**：`js/app.js` 用 `getElementById` 绑定全部控件，隐藏步骤必须用 CSS（`display:none`）而非从 DOM 移除，否则事件绑定与计算全部失效。**这是整个改造最大的技术风险点。**

**验收**：无长句、无解释性段落；每行 ≤ 3 个字段；可一键复制为文本 / 导出 JSON（复用现有 `#btnJson`）。

### R4 — 文字总量砍掉，改用折叠与悬浮气泡

**你的意思**：页面文字太多，用折叠展开或 tooltip 承载。

**我的翻译**：把当前页面上所有「铺开的说明文字」分三类处理：

| 类型 | 现状 | 处理 |
| --- | --- | --- |
| **术语解释**（.glossary 的 8 条 dt/dd） | 折叠在一张卡里，占首屏 | 移到全局「术语」抽屉（右下角按钮或 `?` 悬浮球），或做成关键词 hover 气泡 |
| **卡片内提示**（显卡适配主板、PCIe 5.0 SSD、电源校验规则、导出编码说明等 .note） | 每处 2~4 行小字，共 6 处 | 卡片标题旁加 `ⓘ` 图标，**hover / focus 弹出气泡**，卡内只留标题 |
| **免责与数据可靠性**（.banner + 数据来源区块） | 一整条横幅铺在顶部 | 降级为页脚一行「数据为估算 · 查看依据」，点击展开 |

**验收**：页面上**可见的连续文字段落**（>2 行）数量从当前 ~10 处降到 ≤2 处；所有被折叠内容的文字一个字都不删（可被搜索、可被打印）。

**重要**：收纳 ≠ 删除。术语表和数据来源是这工具的**可信度资产**，必须能被找到，只是不该糊在第一屏。

### R5 — 数据来源独立 + 多维描述数据库

**你的意思**：把数据来源独立出来，构建多维描述数据库，从多个方面描述显卡/CPU/电源的性能参数，让决策更有依据。

**我的翻译**：分两步。

**第一步：数据与展示彻底分离（当前是耦合的）**
- 现状：`js/db.js` 里 `SOURCES`、`GPUS`、`PSUS` 等与装配逻辑写在同一个文件，826 条显卡数据由 `db-aib.js` 的规则生成器在运行时推导。
- 改为：`data/` 目录按领域拆文件（sources / cpus / gpus / aibs / psus / ram / storage / coolers / fans / cases / mobos / extras），各自只导出纯数据；新增 `data/schema.md` 定义字段语义；运行时仍由 `db.js` 装配（**保持无构建步骤**）。
- 好处：数据可单独 review、可单独提 PR、不会因为改样式碰到数据。

**第二步：增加「决策维度」字段（不是堆参数，是补决策依据）**

| 维度 | 字段 | 为什么 DIY 用户需要 |
| --- | --- | --- |
| 功耗语义 | `tdp` / `maxTurbo` / `ocPeak` / `transient` 倍率 / `transientMs` | 现在只有数值，没有「这个数在什么条件下成立」 |
| 供电要求 | `connector` / `pcie8pin` / `eps8pin` / `recPsu` | 决定电源接口够不够 |
| 物理约束 | `length` / `slots` / `radiator` / `height` | 决定机箱装不装得下 |
| 上市与价格 | `released` / `price` / `priceRange` | 判断性价比与代际 |
| 获取渠道 | `segment`（mainstream/budget/legacy/used）/ `availability` | **新增**：区分新品/二手/散片/矿卡 |
| 数据可信度 | `confidence` / `source` / `sourceDate` / `verifiedBy` | 现在有 confidence 和 source，**缺 sourceDate 与复核标记** |
| 用户决策辅助 | `note` / `caveat` / `goodFor` / `avoidIf` | **新增**：一句话说清「适合谁 / 什么情况别买」 |
| 平台兼容 | `socket` / `memType` / `formFactor` / `atxVersion` | 已有部分，需统一命名 |

**验收**：
- 任取一条数据，能回答：这个数字从哪来、什么时候的、可信度几级、适用于什么场景、有什么坑；
- `data/schema.md` 里每个字段都有：类型、是否必填、单位、示例、语义说明；
- 现有 826 条显卡数据在迁移后**计算结果完全不变**（用同一组测试配置比对迁移前后输出）。

**风险**：字段一多，录入成本暴涨。**必须给每条字段标注「必填 / 选填」**，选填字段缺失时 UI 要优雅降级（显示 `--`），不能因为缺一个 `goodFor` 就让页面报错。

### R6 — 数据覆盖面：补二手 / 老平台 / 低瓦数段

**你的意思**：DIY 人群不都用主流硬件，很多人用便宜的二手或通用市场硬件，这部分要考虑进去。

**我的翻译**：这是**当前最大的产品短板**。实测覆盖面：

| 类别 | 当前 | 缺口（DIY 二手市场的真实主力） |
| --- | --- | --- |
| CPU | 164 款：Intel 10~14 代 + Ultra 200S；AMD AM4/AM5 全系（Ryzen 1000~9000） | 覆盖尚可，缺 **Xeon E5/E3 洋垃圾**、**老 i5/i7 已含**、缺 T 系列低功耗版 |
| 显卡 | 826 个板型，但**只有 RTX 50/40 + RX 9000/7000** | **GTX 10/16 系、RTX 20/30 系、RX 500/5000/6000 系、Intel Arc、GT 系列亮机卡**——这些是二手市场绝对主力 |
| 电源 | **仅 24 款**，550~1600W，集中中高端 | **400~550W 入门段几乎空白**；缺航嘉/长城/金河田/爱国者等国产走量型号；缺二手常见的老款 |
| 主板 | 有，但未核实条数 | 老平台芯片组（B85/B250/B360/B450/A320） |
| 内存 | 16 条 | DDR3 平台（二手办公机大量存在） |
| 存储 | 9 条 | SATA 老 SSD、机械盘容量段 |

**你的选择：按「够用就行」扩**。落地方案：
1. 每个类别补**二手市场 Top 20~30 热门型号**，不追求穷举；
2. 新增 `segment` 字段区分 `new` / `budget` / `legacy` / `used-market`，UI 上提供**筛选开关**「只看我这种平台」；
3. 老硬件的功耗值用 `confidence: 'estimate'` 并注明推算依据（同架构同规模均值），**绝不假装是官方数据**。

**验收**：能完整配出一套 2018 年的主流二手配置（如 i5-8400 + GTX 1060 6G + B360 + 8G DDR4 + 450W 电源）并给出合理推荐；能配出一套洋垃圾（E5-2680v4 + X99）——**如果 Xeon 不做，至少在界面上明确说明「本工具不含 HEDT/工作站平台」**。

### R7 — 「提交新硬件 / 纠错」近乎没有功能；免责声明别当狗皮膏药

**你的意思**：这段（指反馈表单）几乎没功能；免责声明该做，但不能一直糊在脸上。

**我的翻译**：

**(a) 反馈功能的真实问题**：当前流程是「填表 → 存 localStorage → 自己复制 JSON 发给维护者」——**用户根本不会这么做**，等于零功能。三条改法：
1. **最低成本可用**：一键生成**预填好的 GitHub Issue 链接**（`https://github.com/LightningZ-MSI/-/issues/new?title=...&body=...`），用户点一下就带着数据跳转到 Issue 页，这是静态站唯一真正可用的收集通道；
2. **本地即时价值**：用户提交的硬件**立刻写入本人的 localStorage**，并在下次计算时**可被自己选用**（标为「我的自定义硬件」）——让提交对用户本人立刻有用，而不是只对维护者有用；
3. **引导式录入**：表单改为**按类别动态显示字段**（选「显卡」才显示 TBP / 接口 / 长度），并做基本校验（数值范围、必填、重复 id 检测），而不是现在的 6 个通用字段。

**(b) 免责声明的定位**：
- 你说得很准——**免责声明应该是一次性的、克制的**，而不是留在页面上的常驻横幅。
- 改法：首屏**不放**；首次访问时以**一次性提示条**出现（可关闭，关闭状态存 localStorage）；之后仅保留页脚一行「数据为估算 · 依据与局限」，点击展开全文。
- 「数据来源」区块保留，但移到页面底部并默认折叠。

**验收**：举报入口在 3 次点击内可达；生成的 Issue 链接可直接提交；提交的自定义硬件在本机可被计算使用。

## 2. 我判断「不该做」的事（请你确认）

| 你的话可能会推出，但我建议不做 | 原因 |
| --- | --- |
| 引入构建步骤（webpack/vite）来管理数据 | 你的优势是「纯静态、可双击打开、GitHub Pages 直传」。引入构建会让维护成本陡增，收益不明显。**建议保持 data/*.js 由 `<script>` 引入。** |
| 引入前端框架（React/Vue）重写 | 现有 `app.js` 56KB 已跑通全部逻辑，重写风险极高且不产生用户价值。**建议在原结构上做增量改造。** |
| 做真正的后端 / 数据库 | 静态站是你的传播优势。用「GitHub Issue + JSON」做人工汇聚即可。**建议不引入服务器。** |
| 把术语表、数据来源彻底删掉 | 这是可信度资产。**建议只做收纳，不删除。** |
| 一次性把所有硬件数据补齐 | 工作量不可控且容易烂尾。**建议分批：先补二手 Top 30，跑通流程后再扩。** |

## 4. 视觉会审补充（会审后新增，🔴 标记为原解读遗漏）

会审报告全文见《03-UI会审报告.md》。以下是**改变了方案优先级**的关键发现——它们不是视觉问题，是**功能性缺陷**：

### R9 🔴 — 空态会给出「全部匹配」的绿色对勾，并推荐 3 款电源

**问题**（会审基于 `engine.js:317-318,521-562` 与 `app.js:583-610,636-648,695-698` 的代码路径推断）：
- `subtotal=0` 时 `recFloor = roundUpStandard(0×1.3)` 取到标准瓦数表第一项 `450`；
- `pickPsus(450,450)` 在没选显卡、没选机箱时 `compatible()` 全部返回 true → 24 款电源里 ≥450W 的全进候选池 → **渲染出 3 张真实电源卡**，带型号、接口数量、「负载率 0%」、参考价；
- `renderIssues` 在问题列表为空时输出绿色 ✓「未检测到兼容性问题 · 所选硬件组合的插槽、板型、尺寸、供电接口与内存规格均匹配」。

**结论**：**什么都没选却打勾说「全部匹配」，还推荐了三款电源。**这比任何配色问题都严重——它直接摧毁工具的可信度。

**验收**：
- 未选 CPU/GPU 时，兼容性检查返回「未知」并渲染中性态（灰色 `◌`），**任何情况下不得出现 ✓**；
- `subtotal <= 0` 时 `pickPsus` 返回 `null`，电源推荐区显示空态引导；
- hero 初值用 `—` 或骨架屏，不要写死 `0 W / 0 W / 0 W`。

### R10 🔴 — 首访静默灌入 RTX 5090 旗舰预设

**问题**：`app.js:1093` `if (!restored) applyPresetSilent('flagship')`。新用户第一眼看到的**不是自己的配置，而是别人机器的 1200W+ 推荐值**；同时 header 里还摆着「载入示例配置」按钮（暗示当前没有示例）→ **状态与按钮文案自相矛盾**。

**验收**：首访渲染**空配置**，用一个显式的大按钮「载入示例（RTX 5090 旗舰配置）」作为入口；`localStorage` 有记录时才恢复。

### R11 🔴 — 推荐瓦数在移动端/平板上根本看不到

**问题**：
- `.sticky-col{position:sticky;top:74px}` **实际不生效**——右列内容高度远超视口，sticky 只在元素比视口短时才有意义。结果是用户在左列改第 3 步显卡或第 6 步存储时，「推荐电源」早已滚出视口，**改完看不到任何数字变化**。
- `≤1180px` 整列变单列，结果列被排到 10 张配置卡之后 → **平板竖屏与手机要滚约 10 屏才第一次看到瓦数**。

**验收**：
- 任何视口宽度下，「推荐 XXX W」都必须可见：桌面端做成真吸顶条（总高 ≤80px，只放推荐值 + 错误计数），或者每个改动点就地显示差值（`750W → 850W`）；
- 移动端底部常驻一条「推荐 850W」把手，可上滑展开完整报告。

### R12 🔴 — 功耗明细表在窄屏被裁掉且无法横向滚动

**问题**：`table.detail` 没有横向滚动容器，而 `.card{overflow:hidden}` + `th{white-space:nowrap}` + `.wt{white-space:nowrap}` → 360px 宽下表格最小内容宽度超出卡片，**右侧列（瓦数/来源）被直接裁掉，用户也无法横向滚动**。

**验收**：表格套 `overflow-x:auto` 容器；或窄屏改为「一硬件一卡片」。触控目标全部 ≥44px（当前按钮约 35px、删除键 32px、开关 38×21、复选框 15×15）。

### R13 🔴 — 可达性有整片空白

**问题清单**：
- **零 `aria-*` / `role`**：`#toast` 不是 `aria-live`，导出提示读屏不可见；`.hero` 数字与 `#recoBig` 每次改动都变却**没有任何 `aria-live`** → 读屏用户改完配置不知道结果变了；
- **所有 `<label>` 都没有 `for/id` 关联** → 每个下拉框在辅助技术里都是**无名控件**；
- **页面没有可见 `<h1>`**（唯一的在 `.print-only` 里被 `display:none`）→ 标题层级直接从 20 个 `<h2>` 开始；
- **全站零 `:focus-visible`**；`.switch input{display:none}` → 键盘 Tab 停到开关上却**没有任何可见指示**；
- **`prefers-reduced-motion` 零处理**。

**验收**：读屏能听到「推荐电源 850 瓦」的变化；每个控件都有可访问名称；键盘 Tab 全程可见；`reduce-motion` 生效。

### R14 🔴 — 浅色主题的蓝色是不达标的

**问题**：`html[data-theme="light"]` 只覆盖了 accent/warn/error，**没有重定义 `--blue`**。`#4c9aff` 在白底约 **2.9:1** → `.hero .v.blue`（26px/700，大文本门槛 3:1）**刚好不过关**；`a{color:var(--blue)}` 的正文链接与 `.psu-pick .pr` 参考价明显不达标。深色下 `--text-mute #6b7d92` on `#131a23` ≈ 4.2:1，也低于 4.5:1，而它承载了所有 9.5~11.5px 小字。

**验收**：两套主题的全部文本对比度 ≥4.5:1（大字 ≥3:1），用工具实测而非估计。

### R15 🔴 — 四处 `example.com` 占位没替换，分享卡片是坏的

**问题**：`canonical` / `og:url` / `og:image` / `twitter:image` **四处仍是 `https://example.com/`**（作者自己在注释里写了「部署后请替换共 4 处」）。→ 线上分享到微信/飞书时**抓不到图**。同时 og-image 本身有问题：右上有一团纯装饰青绿 glow 铺在空无一物的右半张上；四格指标里第 4 格是规格名（ATX 3.1）而前三格是计数，量纲混乱；把「826 个板型」做成主视觉，但其中**只有 23 条有来源**。

**验收**：四处 URL 换成真实域名；og-image 去掉装饰 glow、删掉第 4 格、把「有来源」而不是「最大虚数」做成主张，并加一张真实界面截图。

### R16 — 视觉层面可直接落地的具体清单

> ⚠️ **注意**：R9~R15 已在**本地代码**里逐行核对过，**确认依然存在**（见《04-构建方案》第零节）。
> 但下表 R16 是**基于线上旧版**的会审结论，而本地已改过一版——对应关系如下：

| 项 | 会审说的（线上旧版） | 本地现状 | 还要不要改 |
| --- | --- | --- | --- |
| 未使用变量 | `--purple` 零引用 | ⚠️ 现在**有引用**了（`--purple: #a45cff` 作提示色） | 按 ROG 方向评估是否保留 |
| 强调色语义 | `--accent` 承担 **8 种语义** | ❌ **恶化了：34 处** | ✅ 必须收敛到 2 处 |
| 字号 / 字重 | 15 档 / 5 档 | ❌ **恶化了：18 档**（9.5~40px） | ✅ 必须收到 5 档 |
| 数字字体 | mono 栈无中文字体，空态 40px 中文挤进最大槽位 | ❌ **仍存在**：`style.css:332` 40px + `app.js:584` 中文 | ✅ 中文禁止进 `.big` |
| `.idx` 徽标 | 亮绿实心方块重复 19 次 | 需重新核对 | 按 ROG 方向统一 |
| 卡片形态 | 配置列 + 结果列完全同构 | ⚠️ 有 `ui.js` 折叠，但形态仍同构 | ✅ 输入区与报告区分离 |
| toast | 99px 胶囊 + 满饱和实底，全页最亮 | `transition:all` 似已部分修 | 统一改直角深底 |
| 动效 | `transition:all` | ⚠️ **新增了 `bolt-breathe 2.5s infinite` 呼吸发光** | ✅ 删除 |
| 圆角 | 10px | ❌ **加大到 14px** | ✅ 收到 2px |
| 装饰渐变 | 3 处 | ❌ **增加到 9 处** | ✅ 只保留负载/进度条 |
| AI 味最强信号 | 【规则引擎，非 AI 模型】+ ✨ | 需核对是否已删 | 若在，直接删 |

**结论**：上一轮改版**解决了结构问题，但把视觉问题放大了**。Phase 1.0 必须先止损（删动画、收 accent、收字号），Phase 4 再按 ROG 规范重建。

**另外，会审给出了「要避免的廉价奥创仿品元素」**（这条很重要，防止我们改过头）：
- 满屏红黑发光 / 红色径向背景（低端屏出色带，红绿同屏立刻变电竞杂牌）
- **中文用斜体或全大写宽字距**（中文无真斜体，浏览器机械倾斜很脏）
- 平行四边形/斜切按钮（`transform:skew` / `clip-path` 边缘抗锯齿露馅，中文更难读）
- 装饰性环形仪表、网格线、扫描线、粒子背景
- 整页开机动画 / 逐卡淡入 / **呼吸发光**（奥创本身就被骂启动慢）
- **不要照搬奥创的信息密度**——奥创服务「已买华硕硬件的人」，本页服务「还没花钱、正在比价的人」，**结论必须先于参数**

---

## 5. 一句话总结这份解读

> 你要的不是「换皮」，而是把**一个数据堆叠的工程师工具**，改造成**一个分步向导式的选型助手**：一次只问一件事，随时能看到那个瓦数，所有解释收进气泡，数据可信度可查、覆盖面包含二手老平台，红黑白三色、直角、无渐变的 ROG 质感。
>
> 而且会审发现：**在动视觉之前，必须先修三个功能性缺陷**——空态谎报「全部匹配」、首访静默灌旗舰预设、手机上根本看不到推荐瓦数。这三条不修，UI 改得再漂亮也不可信。
