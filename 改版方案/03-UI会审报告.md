## 一、AI 模板感诊断（证据级）

### 1. 配色

| 证据 | 事实 | 判定 |
| --- | --- | --- |
| A | `--purple:#a97bff` 在 style.css 里**零引用** | 一次性生成调色板的残留 → 删除 |
| B | `--accent` 一色承担 **8 种语义**：`.card>h2 .idx` 底、`.scenario.on` 边、`.conf.official` 字、`.reco` 边、`.hero .v.accent`、`.issue.ok`、`.switch` 选中轨、`.tag.on` | 强调色满页都亮 → 用户无法用颜色判断「哪里是结论」 |
| C | 三处渐变：`.logo .bolt`（135° accent→blue，实测 `#37CAAF`→`#44AEDF`）、`.reco`（淡出到 transparent）、`.card.guide>h2`（90° 淡出） | 两个典型 AI 指纹同时出现 |
| D | og-image 右上有一团纯装饰青绿径向 glow（峰值 `#13342F`，横向铺满 x≈700–1190），正好盖在空无一物的右半张上 | 「AI aurora glow」——拿渐变填内容空缺 |
| E | og-image 四格指标条：3 格是计数（164/826/23），第 4 格是规格名（ATX 3.1） | 同槽位混放不同量纲 → 先有版式后填内容 |
| F | 826 个板型里只有 **23 条**有官方/评测来源（`aibCatalogMeta.explicitCount=23`），og-image 却把 826 做成主视觉 | 把最大的虚数当主张，而不是把「有来源」当主张 |

**其他模板残留**（功能性，不止视觉）：
- 🔴 `canonical` / `og:url` / `og:image` / `twitter:image` **四处仍是 `https://example.com/`**（作者自己在注释里写了「部署后请替换共 4 处」，未替换）→ 线上分享卡片实际抓不到图。
- 仍在用 `<meta name="keywords">`（已无 SEO 价值）。
- `<meta name="author" content="台式机功耗计算器">` 把产品名当作者。

### 2. 图标与图形语言

- emoji 清单：`⚡`（header logo，放在 30×30 青蓝渐变块里）、`☀/🌙`、`⚠️`，结果列徽标 `★ ! ↑ ✨ ≡ ⤓ § ＋` 共 19 处，删除键 `✕`，甚至把 `⚠` 拼进 `<option>` 文本（`app.js:262-263`）。
- **为什么一眼识破**：
  1. `.idx` 是 accent 实底 + 深墨字 `#04150f`，文本符号（★ § ≡ ⤓ ＋）能吃掉深墨色，但 `✨` 是彩色 emoji 永远亮黄 → 结果列那颗「贴纸」格外突兀；`⚡` 自带橙黄渐变撞在青蓝渐变块里，三色打架。
  2. 符号**三套不同源**：数字（1~10）/ 文本符号 / emoji，光学大小与基线都不齐（`§ ≡` 偏上、`⤓` 偏下、`＋` 是全角）。
  3. emoji 在 Windows / Apple / Android 渲染完全不同 → 视觉不可控。
- **反证（作者有能力做对）**：`favicon.svg` 用的是纯矢量闪电 path，与 header 的 emoji `⚡` 是两个不同品牌标记 → 品牌资产自身不一致。

### 3. 排版层级

- **15 档字号**：30 / 26 / 22 / 19 / 16 / 14 / 13 / 12.5 / 12 / 11.5 / 11 / 10.5 / 9.5 px……其中 12 / 12.5 / 11.5 / 11 / 10.5 五档在屏幕上无法区分 → 等于没有层级，只剩「到处都是小字」。**用 0.5px 差假装层级是最典型的 AI 排版。**
- **5 档字重**（400/500/600/700/800）全用，同一 14px 内混排 500/600/700/800。
- 🔴 **数字排版硬伤**：`.hero .v` / `.reco .big` / `.psu-pick .w` 都用 `var(--mono)`（栈内**无一个中文字体**），而空态时 `#recoBig` 要显示中文「请先选择硬件」（`app.js:584`）→ 一个 30px/800 的中文句子占用全页最大字号槽位，且字体回退导致「中文雅黑、数字 Consolas」同段两种字形。
- 同一个单位「W」两套写法：`.hero .v small{font-size:13px}` vs `app.js:591` 内联 `font-size:18px`。

### 4. 卡片形态与节奏

- `.card` 一个类包打天下：`border-radius:10px` + `1px solid #23303f` + `margin-bottom:16px`，配置列 11 张 + 结果列 8 张**全部同构**。唯二例外只改了边框色。
- **为什么一眼识破**：真实产品里「输入区」和「报告区」形态必须不同（输入是表单容器，结论是仪表），这里完全同构、只靠左右位置区分 → 用户视线找不到层级，只能从头读到尾。
- 全页只有 `.card-body.tight` 一处间距变化 → 节奏机械。

### 5. 文案语气（AI 客服腔）

- 顶部 banner：「关于数据可靠性——请先读这一段」+ 加粗「电源选型的本质是估算」+ 4 个 inline 徽标。
- 引导卡：「我不会选，先用示例试试」/「知道了，收起」/「看不懂那些术语？（点开有解释）」。
- 🔴 **全页最强 AI 味信号**：`index.html:437` 的 hint 写着【规则引擎，非 AI 模型】，还配 `✨` 星光 emoji——**给规则引擎贴 AI 功能图标，同时主动否认自己是 AI**。
- `.note` 段落全是「——」+「：」的二次补充节奏；空态文案「在上面选好 CPU 和显卡，这里就会出现结果。」
- **模式**：每段先自我解释再给信息 + 用括号/破折号二次补充 + 对「我可能算错」反复致歉式声明。

### 6. 动效与细节

- `button{transition:all .15s}`（`all` 包含 background/color/border → hover 时整块闪绿）、`.toast{transition:all .28s}`。
- `.toast` 是 99px 全圆角胶囊 + 满饱和 accent 实底 + 大阴影 → **一个「已复制」提示被做成全页最亮元素**，喧宾夺主。
- `::-webkit-scrollbar` 仅 WebKit，Firefox 无对应 → 两平台观感不一致。
- `header.top{backdrop-filter:blur(12px)}` 无 `@supports` 降级。

### 7. 🔴 空态与边界（0 W）—— 比配色严重得多

- **看到的**：`index.html:391/396/401` 把 hero 三个数字写死为 `0 W`，`:409 #recoBig` 写死「— W」，结果区多个容器为空 → 脚本执行前首屏就是「0 W / 0 W / 0 W + 三张空卡」。
- **推断（基于 `engine.js:317-318,521-562` 与 `app.js:583-610,636-648,695-698` 代码路径）**：`subtotal=0` 时 `recFloor=roundUpStandard(0×1.3)` 取到 `STANDARD_WATTS[0]=450`；`pickPsus(450,450)` 在无显卡无机箱时 `compatible()` 全返回 true → 24 款里 ≥450W 的全进池 → **`.psu-picks` 会渲染 3 张真实电源卡**（含型号、接口数、「负载率 0%」、参考价）；同时 `renderIssues` 在 issues 为空时输出绿色 ✓「未检测到兼容性问题 · 所选硬件组合的插槽、板型、尺寸、供电接口与内存规格均匹配」。
- **没选任何硬件却打勾「全部匹配」，还推荐了三款电源。这比任何配色问题都伤可信度。**
- 🔴 而且多数用户看不到这个空态：`app.js:1093` `if (!restored) applyPresetSilent('flagship')` → **首访自动灌入 RTX 5090 旗舰配置**。新用户第一眼看到的是别人机器的 1200W+ 推荐值；header 里却还摆着「载入示例配置」按钮（暗示当前没有示例）→ **状态与按钮文案矛盾**。

## 二、信息架构与注意力

**首屏视线落点（推断，基于 DOM + CSS 权重）**：
1. 全宽橙色 banner（首屏最亮最宽的文本块）
2. 左列第一张「?」引导卡（唯一被特殊着色的卡，约 500px）
3. 右侧 `.hero` 三格 26px 数字（accent/blue/warn **三色地位完全相同**）
4. 真正要买的钱数 `.reco .big`（30px）——**只排到第 4 顺位**

**核心结论是否首屏可见**：1440×900 勉强可见，但只是第 4 顺位，且 30px vs 26px 只差 4px。**≤1180px 整列变单列后结果列被排到 10 张配置卡之后 → 平板竖屏和手机要滚约 10 屏才第一次看到瓦数**，header 里也没有「跳到结论」锚点。

**信息顺序错了**：用户要的是推荐值，页面顺序却是「规划功耗 → 场景预期 → 瞬时峰值 → 推荐电源」。前三个是过程，第四个才是答案。

**视觉权重最高但重要性最低（按该降级排序）**：
1. 顶部橙色数据可靠性 banner
2. 左侧「?」引导卡（含 8 条术语解释）
3. 结果列「配置平衡建议」里的**整机预算输入框**——表单混进结论区
4. 结果列「数据来源」区块
5. 「导出报告」下方的编码/打印说明
6. header 的 `#dbCounts` 统计胶囊——**只读统计与可点操作长得一模一样**
7. `.card>h2 .idx` 绿方块出现 **19 次**，是全页重复最多的强色块

🔴 **结构性硬伤**：`.sticky-col{position:sticky;top:74px}` **实际不生效**——右列内容高度远超视口，sticky 只在元素比视口短时有意义。结果是用户在左列改第 3 步显卡或第 6 步存储时，「推荐电源」早已滚出视口，**改完看不到数字变化**（无任何就地反馈）。

## 三、ROG 奥创对标（差异与落地建议）

> 原报告依据公开资料与既有认知；**本项目的《01-设计系统-ROG奥创.md》已改为依据华硕官网真实 UI 截图**，以那份为准。此处保留其「应避免的廉价仿品元素」清单。

**奥创真实视觉特征**：近黑底、强调色极少（红只出现在选中/品牌标识/关键动作）、圆角极小（0–4px，接近直角）、1px 深灰边框、几乎不用大阴影、**选中态是「左侧 3–4px 亮色竖条」或「标签页底部 2px 下划线」而不是整块变红**、导航是左侧固定 icon+文字列表、**数字主要靠环形/条形仪表 + 负载轨道表达，而不是三宫格数字**、动效快（120–160ms）无 bounce。

**必须避免的「廉价仿品元素」**：
- 满屏红黑发光 / 红色径向背景（低端屏出色带，红绿同屏立刻变电竞杂牌）
- 中文用斜体或全大写宽字距（**中文无真斜体，浏览器机械倾斜很脏**）
- 平行四边形/斜切按钮（`transform:skew` / `clip-path` 边缘抗锯齿露馅，中文更难读）
- 装饰性环形仪表、网格线、扫描线、粒子背景（该学的是「用轨道表达负载率」这个**表达方式**，不是把仪表当壁纸）
- 大面积 RGB/霓虹渐变描边卡
- 整页开机动画 / 逐卡淡入（奥创本身就被骂启动慢）
- **不要照搬它的信息密度**——奥创服务「已买华硕硬件的人」，本页服务「还没花钱、正在比价的人」，**结论必须先于参数**

## 四、移动端与可达性（基于代码推断）

**<640px 具体问题**：
1. `.layout` 在 1180px 就变单列 → 「答案被推到 10 张卡之后」在 iPad 竖屏同样成立。
2. `.hero` 在 640px 变 3 行（约 240px），顺序仍是过程数字在前。
3. `.grid3/.grid2 → 1 列`：导出按钮 3 行、反馈表单 3 行、GPU 三级联动各占整行；`.chk-grid` 也变 1 列。
4. 🔴 **最可能的真实移动端事故**：`table.detail` **没有横向滚动容器**，而 `.card{overflow:hidden}` + `th{white-space:nowrap}` + `.wt{white-space:nowrap}` → 360px 宽下表格最小内容宽度超出卡片，**右侧列（瓦数/来源）被直接裁掉且无法横向滚动**。
5. `.storage-row{grid-template-columns:1fr 74px 32px}` → 360px 下型号 select 只剩约 200px，长型号名截断。
6. **触控目标普遍偏小**：button ≈ 35px 高（建议 ≥44px）；`.storage-row .del` 32px；`.switch .track` 38×21；`.chk input` 15×15；`.chk input[type=number]{width:52px}`；`.seg button{min-width:68px}` 在 6+ 品牌时折成 2–3 行小按钮。
7. `header.top` 是 `flex-wrap` 的 logo + 3 按钮 + 1 统计胶囊 → 窄屏折成 2–3 行；同时 `sticky + backdrop-filter` → 手机上约 100px 半透明条常驻，既遮内容又是性能负担。
8. `backdrop-filter` 无 `@supports` 降级。
9. `select` 未重置 `appearance` → iOS/Android 原生下拉弹层是浅色，与深色页面突兀。

**对比度（按 CSS 变量换算，非渲染实测）**：
- 深色：`--text-mute #6b7d92` on `--panel #131a23` ≈ **4.2:1**，低于 AA 的 4.5:1，而它恰好被用于 9.5~11.5px 的小字（`.conf`、`.hero .k`、`.card .hint`、`th`）。
- 浅色：`--text-mute #7b8b9c` on `#fff` ≈ 3.5:1；`--warn #b87800` on `#fff` ≈ 3.7:1，而 `.issue.warn b` 是 12.5px 正文语义 → 不合格。
- 🔴 **明确的功能性缺陷**：`html[data-theme="light"]` 只覆盖了 accent/warn/error，**没有重定义 `--blue`**。于是 `#4c9aff` 在白底 ≈ **2.9:1**：`.hero .v.blue`（26px/700，大文本门槛 3:1）**刚好不过关**；`a{color:var(--blue)}` 的正文链接与 `.psu-pick .pr` 参考价明显不过关。

**焦点可见性**：
- 全站**零 `:focus-visible`**；`select,input{outline:none}` 后用 `:focus` 边框 + 光晕替代（对键盘用户尚可）。
- 🔴 按钮 / `.btn` / `.scenario` / `.seg button` / `details summary` 都没有自定义焦点样式。
- 🔴 `.switch input{display:none}` → 键盘 Tab 会停到开关上但**屏幕上没有任何可见指示**。
- 🔴 **零 `aria-*` / `role`**：`#toast` 不是 `role="status"`/`aria-live`，导出提示对读屏不可见；`.hero` 数字与 `#recoBig` 每次改动都变却**没有任何 `aria-live`** → 读屏用户改完配置不知道结果变了。
- 🔴 所有 `<label>` 都没有 `for/id` 关联 → 每个下拉框在辅助技术里都是**无名控件**。
- 🔴 **页面没有可见 `<h1>`**：唯一 h1 在 `.print-only`（屏幕上 `display:none`）和 `<noscript>` 里，`.logo` 是 div → 标题层级直接从 20 个 `<h2>` 开始。
- 🔴 **`prefers-reduced-motion` 零处理**（401 行 CSS 无命中）。
- 加分项：`@media print` 做得完整（隐藏配置列/按钮、强制黑白数字、`break-inside:avoid`、链接补 URL）。
