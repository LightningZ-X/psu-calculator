# 台式机整机功耗计算与电源选型工具

纯 **HTML + CSS + JavaScript** 实现的交互式工具：按所选硬件配置累计整机功率，做兼容性校验，
并给出 ATX 3.1 电源推荐与未来升级空间推演。

**无框架、无构建步骤、无外部 CDN 依赖** —— 双击 `index.html` 即可离线运行。

## 怎么发给别人用

### 方式零：发布成网站（有链接，谁都能访问）

完整步骤见 **[DEPLOY.md](DEPLOY.md)**。三步：

1. 替换占位域名 `https://example.com`（`index.html` 5 处、`sitemap.xml` 3 处、`robots.txt` 1 处）
2. 把 `index.html` / `404.html` / `favicon.svg` / `robots.txt` / `sitemap.xml` / `assets/` / `js/`
   上传到 GitHub Pages 或 Cloudflare Pages
3. 等 1～3 分钟，拿到网址

项目已内置部署所需的全部外围文件：

| 文件 | 作用 |
|---|---|
| `robots.txt` / `sitemap.xml` | 让搜索引擎收录（别人搜"电源计算器"能找到） |
| `404.html` | 自定义 404 页，不会露出托管平台的默认报错页 |
| `favicon.svg` | 浏览器标签页图标 |
| `assets/og-image.png` | 微信/QQ/Twitter 分享时的预览卡片（1200×630） |
| JSON-LD 结构化数据 | 帮助搜索引擎识别为"免费在线工具" |
| `<noscript>` 兜底 | 禁用 JS 或早期爬虫也能读到工具说明 |

`node tools/browsertest.mjs` 末尾会跑**部署就绪性检查**，逐项确认上述文件齐全、
分享图尺寸正确、robots 没把自己挡住，并提醒你还有哪些占位域名没换。

### ⚠️ 不能只发 `index.html`

`index.html` 引用了 `assets/style.css` 和 `js/` 下的 5 个脚本。
**单独把 `index.html` 发出去会白屏** —— 样式和逻辑都加载不到。

好消息是这个工具**零外部依赖**（无 CDN、无框架、不发任何网络请求），所以下面三种方式都能完全离线运行。

### 方式一：单文件 HTML（推荐，最省事）

```powershell
node tools/build-standalone.mjs
```

生成 **`dist/整机功耗计算器.html`**（约 250 KB）。这一个文件就是完整工具，
对方**双击即可使用**，不需要解压、不需要联网、不需要装任何东西。微信/邮件直接发都行。

适合发给不太懂电脑的人 —— 没有"解压到哪""为什么打不开"这类来回。

> 修改数据或代码后，**记得重新运行一次构建脚本**，否则 `dist/` 里还是旧版本。
> `browsertest.mjs` 会检查产物是否过期，过期会直接报错提醒。

### 方式二：打包整个文件夹

把 `psu-calculator` 压缩成 zip 发过去，对方解压后双击 `index.html`。

要点：
- **必须先解压**，不能在压缩包里直接双击
- 解压路径**别带中文或空格**（`C:\Users\张三\我的下载\` 这类路径偶发问题）
- 微信/QQ 会拦 zip，改用邮件或网盘

### 方式三：部署成在线网页

一个链接发给谁都能用，且随时更新：

| 平台 | 做法 |
|---|---|
| **GitHub Pages** | 建仓库 → 上传文件 → Settings → Pages → 选 main 分支根目录 |
| **Cloudflare Pages / Vercel / Netlify** | 直接拖拽文件夹上传，自动出链接 |
| **Gitee Pages** | 国内访问更稳，需实名认证 |

纯静态页面无需任何构建配置，上传即可。若托管平台默认启用 Jekyll，加一个空的 `.nojekyll` 文件。

### 给非专业用户的适配

页面顶部有一张 **「第一次用？看这里」** 引导卡片：

- 3 步上手说明（选硬件 → 看右上角数字 → 留意红色警告）
- 「我不会选，先用示例试试」按钮，循环切换 4 种典型配置
- 可展开的**术语表**（规划功耗 / 瞬时峰值 / TDP / 12V-2x6 / ATX 3.1 / 80 PLUS 等级…）

结果区文字按「结论先行」写：直接显示 **「推荐买 1200W；预算紧张时最低不要低于 1000W」**，
而不是只丢一个系数让人自己算。

## 界面设计（ROG 奥创）

界面按**华硕 ROG 奥创（Armoury Crate）**的视觉语言重做，依据是从华硕官网真实 UI 截图提取的
设计规范。**不是凭空想象的"科技风"，而是有具体 token 与禁用清单的收敛过程。**

### 本轮改版（六项需求）

| # | 需求 | 做法 | 验收 |
|---|---|---|---|
| 1 | **打开页面时把选项收起来，由用户自行打开** | `js/ui.js` 的 `ALWAYS_OPEN` 从 `[1,2,3]` 改成 `[]`。10 张配置卡默认全部收起，只留标题 + 已选摘要；「使用方法」引导卡保持可见作为入口 | `browsertest` 断言「默认全部收起」+ 点开关的展开/收起双向可用 |
| 2 | **换成 ROG 玩家国度之眼，整体带 ROG 斜切文化** | 之眼改成**从官方 logo 图提取的图形本体**（`tools/build-logo.mjs`，见下文），替换原手画形状；`favicon.svg`、`404.html`、分享图同步换掉。分区标记从两条 `>>` 改成 **`///` 三条**（对照真实奥创界面）；斜切只留在分区标记与选中/关键指示条上，**不给容器切角**；斜切永远只切形状不切文字（全站零 `transform: skew` 落在文本上） | `designcheck` 的渐变白名单 / 红色用量 / 形态多样化；`browsertest` 新增「标志与样式表完整性」7 条；7 张截图人工核对 |
| 3 | **去掉「数据来源」界面，改为打开页面时的声明弹窗** | 删掉结果列末尾的「数据来源」卡片与顶部「数据为估算值」免责条，内容全部搬进 `#disclaimerModal`。**保留 `id="sources"` 与 `id="aibCatalogNote"` 原位**（只是换了父节点），所以 `app.js` 一行都不用改 | `browsertest` 专项 13 条：自动弹出 / `role=dialog` / 关闭路径 / 「不再提示」持久化 |
| 4 | **显卡页面的声明也移入弹窗** | 显卡卡里的「关于显卡适配主板」说明与 AIC 可靠性声明一起搬进弹窗；显卡卡现在只有 ① 品牌 ② 世代 ③ 型号 ④ AIC 四行控件，没有任何说明块 | 同上；另断言 `.col-result` 下已不存在 `#sources` |
| 5 | **CPU 也做分类筛选** | 从「一个 164 项的大下拉」改成三级联动：① 品牌按钮（Intel / AMD）② 系列 / 世代下拉（带年份与款数，按「当前在售 / 已停产 / 未发布」分段）③ 型号下拉（按世代分组，组内按 TDP 降序） | `browsertest` 断言切品牌后型号列表只剩该品牌、切世代后列表收窄 |
| 6 | **补 900 系到 30 系老卡数据，关切久远硬件的参与** | GPU 从 22 款扩到 **66 款**，AIC 板型从 826 扩到 **2150**，新增 14 个世代；每个世代带 `segment` 分段，世代下拉的分组名直接写「已停产 · 二手常见」；显卡型号标签带 `[已停产]`；弹窗新增「纯血老卡与二手硬件的提醒」 | `dataaudit` 新增世代元数据自洽 + 老卡存量下限两条硬检查；`browsertest` 断言 NVIDIA 世代下拉里 GTX 900 / 10 系 / RTX 30 系都在 |

> **扩容踩到的一个真问题**：加了老卡之后，引擎的「升级建议」按 `TBP 最大者胜` 选卡，
> 于是 2019 年的 RTX 2070 SUPER（215W）会顶掉 Arc B580（190W）——对一个 2026 年
> 准备升级显卡的人来说这是坏建议（TBP 高 ≠ 性能好 ≠ 买得到）。
> 现在改为**优先在当前在售的型号里挑**，只有预算内一块在售卡都放不下时才退回老卡，
> 并在文案里明确写出「这个余量只够上已停产的老卡」。见 `tools/baseline-diff.mjs`。

### 先修可信度，再改视觉

这一轮最先做的不是换色，而是修掉三个**功能性缺陷**——它们比配色难看严重得多：

| # | 缺陷 | 症状 |
|---|---|---|
| 1 | **空态谎报「全部匹配」** | 什么都没选，页面却打绿勾说「未检测到兼容性问题 · 均匹配」，还推荐 3 款「负载率 0%」的电源，甚至给出升级建议 |
| 2 | **首访静默灌入旗舰预设** | 新用户第一眼看到的是别人机器的 RTX 5090 配置与 1200W 推荐值，而顶栏还摆着「载入示例配置」按钮 |
| 3 | **窄屏看不到结论** | sticky 在单列布局下失效，结果列被排到 10 张配置卡之后，手机要滚约 10 屏 |

第 1 条的根因是引擎把「有没有条目」当成「有没有选硬件」——
默认状态里 `gpuId: '__igpu__'` 会压入一个 0W 条目，于是 `hasSelection` 恒为真。
现值改为判据 **`subtotal > 0`**，并把首访的预设与硬编码默认值（`initCpu` 里的 270K Plus、
`initStorage` 里的一行 SSD）全部移除，空态才真的是空的。

### 三条「反 AI 感」铁律

改完后 `node tools/designcheck.mjs` 会逐条自检，违反任意一条页面就会重新变成「一眼 AI」：

| 铁律 | 做法 |
|---|---|
| **① 一种强调色，且极小面积** | 只有 ROG 红 `#ff0033`，其余全是灰阶；红色实底只出现在 logo、主按钮、开关轨与 4px 指示条上，**不给任何大容器铺红底** |
| **② 不要渐变、不要发光、不要 emoji** | 全站唯一的渐变是双斜杠品牌标记；0 个 CSS 动画、0 个 keyframes；图标全部换成内联 SVG（`stroke: currentColor`） |
| **③ 形态多样化，分组靠亮度** | 卡片不再套「深色面板 + 1px 描边 + 大圆角」的同一套壳；改用**分区标题 + 极细下划线**、**数据行**、**设置行**、**模式选择器** |

### 色彩令牌

| 用途 | 暗色（默认） | 浅色 |
|---|---|---|
| 主内容区 / 次级凹陷 / 顶栏 | `#121212` / `#181818` / `#0a0a0a` | `#f5f5f5` / `#ffffff` / `#ffffff` |
| 描边 | `#2a2a2a` | `#e0e0e0` |
| 唯一强调色 | `#ff0033` | `#d40029`（压深以保证白底达标） |
| 文本四级 | `#ffffff` / `#c8c8c8` / `#8a8a8a` / `#5a5a5a` | `#111` / `#333` / `#5c5c5c` / `#8a8a8a` |
| 状态 | 成功 `#16a34a` · 警告 `#e08600` · 错误 `#ff0033` | `#15803d` / `#9a5b00` / `#c4001f` |

**圆角收到 2px**（浮起表面 4px）——大圆角是「网页模板味」，不是游戏 UI 味。
**字号收敛到 6 档**（11/12/14/15/20 + hero），**字重 3 档**（400/600/700），
不再用 0.5px 的中间档假装层级。

> ⚠️ `--text-4`（`#5a5a5a`）对比度只有 **2.72:1**，只能用于非信息性占位。
> 所有信息性小字（`.hint` / `.note` / 数据行说明 / 表格来源）一律用 `--text-3`。

### 复刻的 ROG 标志性组件

| 组件 | 说明 |
|---|---|
| **ROG 官方锁定版** | 图形本体 + `REPUBLIC OF GAMERS` 字标，**都从官方 logo 图里切出来**，不是手画、也不是用字体模拟。`tools/build-logo.mjs` 读源图像素、按 alpha 抠图、用**行投影**找出图形与字标之间的最大空白带（实测 142px）把两者切开、各自裁到外接框再重着色。产物 `assets/rog-eye.png` + `assets/rog-wordmark.png`。字标是定制字形，网页字体里没有，只能用图 |
| **锁定版的排布** | 顶栏用**横向**锁定版（图形在左、字标在右）—— 顶栏是横向布局，官方那种纵向排布会把产品名挤下去。404 页空间充足，用**纵向**锁定版（图形在上、字标在下），与官方原图完全一致 |
| **标志上色方式** | 用 CSS `mask`：mask 只取 alpha，颜色由 `background: var(--rog)` 提供，所以深浅主题切 `--rog` 时标志自动跟着换，不需要维护两套图。**不给 logo 加底衬色板** —— 官方锁定版是裸标志 |
| **字标的最小尺寸** | 字标是细笔画定制字形，缩到 100px 以下就糊成一团（放大截图核对过），所以顶栏给到 140px；窄屏（≤640px）直接隐藏字标只留图形，因为顶栏里真正需要被读到的是「这是什么工具」 |
| **`///` 三条斜杠分区标记** | Armoury Crate 每个分区标题前的小标记（Aura Sync 的 Basic Effects、Home 的 Systems Monitor / Devices / Operating Mode 都是它）。**是三条不是两条** —— 两条会读成「快进符号 `>>`」，那是另一个语义。纯 CSS 三个 `linear-gradient` 拼出，不用图片；`designcheck.mjs` 断言它确实是三条 |
| **斜切指示条** | 选中项底部的斜切短条 + 关键数值下方的斜切下划条。**斜切只出现在「标记」与「指示条」上，不给容器切角** —— 对照真实奥创界面，面板全是干净矩形 |

| **数据行** | 「标签 ······· 右对齐数值」，替代「一个数据一张卡」。三个核心数字改用它 |
| **设置行** | 「左标签 + 右控件 + 行间细线」，替代 label 在上、input 在下的堆叠式表单 |
| **模式选择器** | 图标 + 文字 + 选中项浅底 + 底部红色斜切条，用于「使用场景」 |
| **关键数值块** | 56px 等宽数字 + 红色 4px 斜切下划条 + 一句话结论 |
| **答案筹码** | 顶栏常驻的「推荐电源 1300–1500 W」，干净矩形；顶栏 sticky 所以任意滚动位置都可见 |

### 让页面「不像 AI 生成的」——具体做了什么

「AI 味」通常不是配色问题，而是几个可指认的坏习惯。这一轮逐条清掉：

| 坏习惯 | 本项目的处理 |
|---|---|
| **同一枚花纹到处贴** | 初版给弹窗的五个小标题、三档电源的角色标签都加了斜切短棒，同一枚 motif 在页面上重复八遍。现在斜切只留在 `///` 分区标记与选中/关键指示条上 |
| **手画一个复杂商标** | 之前那个「之眼」是凭印象画的六边形加三角形，跟真的差很远。改成从官方图里把图形本体抠出来 |
| **给 logo 加底衬色板** | 「圆角/六边形色块里放一个白色 glyph」是模板站与 AI 生成页的典型做法。官方锁定版是**裸标志**，所以这里也去掉了底衬 |
| **每个容器都套同一种壳** | 面板一律干净矩形，不切角不加阴影；分区分组靠标题 + 极细下划线，而不是「深色面板 + 描边 + 大圆角」 |
| **装饰性字幕与空话** | 分区标题右侧的 `.hint` 只写「这一步决定什么」，不写「智能推荐」「一键搞定」这类没有信息量的话 |

> ⚠️ **商标说明**：ROG 之眼与 ROG 红是华硕（ASUS）的注册商标，本项目的图形素材取自华硕公开的
> 官方 logo 图。这是一个**第三方爱好者工具，与华硕没有任何隶属或背书关系**，
> 使用该图形只为呼应它所参照的界面风格。也正因如此，这里**没有**搬用
> "FOR THOSE WHO DARE" 这类 ROG 官方标语 —— 那会让页面看起来像华硕官方产品。

### `js/ui.js` —— 增强层，不碰计算

放在 `app.js` 之后加载，只读取 app.js 渲染出的 DOM：

| 卡片折叠 + 已选摘要 | 往每张卡的 `h2` 注入开关与摘要位；摘要按序号读对应控件当前值，折叠状态记忆在 localStorage。**默认全部收起**（`ALWAYS_OPEN = []`） |

| 移动端结果条 | 底部常驻，数值取自顶栏答案筹码（同源，避免各算一套） |
| 数据声明弹窗 | 打开页面时自动弹出；Esc / 遮罩 / 关闭键都能关；Tab 焦点锁在弹窗内；勾选「不再提示」后按**数据版本**记忆（数据库升版会再提示一次）。URL 带 `?nodisclaimer=1`（或 `#nodisclaimer`）可抑制 —— 截图、分享图与其余回归测试都靠它，否则弹窗会盖住整页让布局断言失真。另暴露 `window.__PSU_DISCLAIMER__` 供测试调用 |

**硬性约束（有测试保障）**：不改任何 `id` / `name` / `data-*`，不改 `engine.js` / `db*.js`，
出错只 `console.error` 不影响主功能。

### 打印（导出 PDF 的唯一实现）

打印会把红色指示条、斜杠标记、渐变、着色底全部**压平为纯色/黑色**，
隐藏配置列与所有按钮，强制展开 `.card.is-collapsed` 与 `details`，取消行数截断。
这些规则由 `designcheck.mjs` 的 6 条断言 + `browsertest.mjs` 的 10 条断言守着。

**脚本加载顺序不可调换**：`db-cpus.js` → `db-aib.js` → `db.js` → `engine.js` → `app.js`。
前两个把数据挂在 `globalThis` 上，`db.js` 负责校验并装配成 `window.HWDB`；
Node 环境下 `db.js` 会自动 `require` 前两个模块，所以 `engine.js` 只需 `require('./db.js')`。

分层原则：**`engine.js` 不碰 DOM**，功耗与兼容性逻辑可在 Node 里完整单测；`app.js` 只负责取输入、调引擎、渲染。

> ⚠️ **维护提醒**：所有源文件均为 UTF-8。不要用 Windows PowerShell 的
> `Get-Content` / `Set-Content` 管道处理这些文件——本环境的 `Get-Content` 默认按 GBK 解码，
> 会把中文内容读成乱码再写回，造成不可逆损坏。用支持 UTF-8 的编辑器直接改。

## 计算逻辑

### 1. 单项功耗取值

| 部件 | 取值规则 |
|---|---|
| CPU | 默认取 **最大睿频功耗**（Intel MTP / AMD PPT）；不锁倍频的型号开启超频后取解锁值或自定义值 |
| 显卡 | 取 **所选 AIC 板型的 TBP**；开启超频后取该板型的 **OC 功耗墙上限** |
| 主板 | 芯片组 + VRM 转换损耗 + 板载网卡/控制器的整板功耗（12-32W） |
| 内存 | DDR5 每条 3.2-6.5W / DDR4 每条 2.4-3.2W（带 RGB 更高），× 条数 |
| 存储 | Gen5 SSD 11W / Gen4 7.5W / SATA 3W / HDD 8W（启动瞬间额外 20-25W） |
| 散热 | AIO = 水泵 5-9W + 风扇（2-3 只）；风冷 = 1-2 只风扇 |
| 风扇 | 单只 1.68-3.6W（ARGB 型号更高） |
| ARGB | 每通道 3-5W（默认按 4W） |

### 2. 三个总量

```
规划功耗   = Σ 各部件功耗上限            ← 峰值合计，电源选型的依据
场景预期   = 规划功耗 × 负载系数          ← 该场景下的典型实际功耗
瞬时峰值   = 规划功耗 − 显卡 + 显卡 × 尖峰倍率 + 硬盘启动功耗   ← 估算
```

负载系数按场景：办公 0.75 / 游戏 0.95 / 创作 1.00 / 极限 1.08。

**为什么要区分**：各部件同时满载在现实中几乎不会发生（游戏时 CPU 很少跑到 MTP），
但电源必须在最坏情况下不出问题。所以选电源用前者，理解真实功耗用后者。

### 3. 电源推荐（双阈值模型）

```
安全下限 recFloor = 规划功耗 × 1.30  → 向上取整到标准瓦数（严格，不容差）
推荐目标 recIdeal = 规划功耗 × 冗余系数（1.40~1.50）→ 向上取整（容许 1% 欠量）
最终推荐 = recFloor ~ recIdeal（两者相等时只显示一个数）
```

- 冗余系数按场景：办公 1.30 / 游戏 1.40 / 创作 1.50；开启超频或存在机械硬盘时强制 ≥1.40~1.50
- 同时受**显卡厂商建议整机电源**约束（如 ASUS 对 5090 全超频平台建议 1000W、
  微星对 5090 闪电建议 1600W），取较大者作为下限
- 标准瓦数序列：450 / 500 / 550 / 650 / 750 / 850 / 1000 / 1200 / 1300 / 1500 / 1600 / 2000
- 若理想目标超出 2000W（消费级电源上限），**约束到 2000W 并如实说明缺口**，
  而不是给出一个买不到的非标准瓦数

**两个刻意设计：**

1. **给区间而不是单一数字**。单一阈值向上取整会"跳档"——1327W 直接跳到 1500W，
   既掩盖真实余量，也可能让你多花一两千块。给出区间后，1300W 与 1500W 的取舍交给你判断。
2. **推荐目标容许 1% 欠量**。电源瓦数序列在高段跨度极大（1600 → 2000 差 25%），
   若需求仅比某个标准瓦数高出不到 1%（如 1606.6W vs 1600W），强行跳到下一档
   会让用户多花上千元却买不到实际安全性。模型的功耗数据本身不确定度远大于 1%，
   因此 1% 容差是合理的。**安全下限不启用容差**——它是硬性底线。

> 验证：为「RTX 5090 闪电（默认 800W）」配置整机，本工具算出规划功耗 1147.6W，
> 推荐 **1600W**，与微星官方建议的 1600W **完全一致**。这条有专门的测试断言。

### 4. 电源候选推荐

先按**硬条件过滤**（瓦数达标 + 机箱电源规格匹配 + 12V-2x6 / PCIe 8pin 接口数量足够），
再按**角色**推荐三个方案：性价比之选（达标前提下最便宜）/ 均衡之选（贴近安全下限的型号中认证最高）/
旗舰之选（瓦数最高、认证最高）。

> 刻意**没有**按数据库的"基础/均衡/旗舰"字段机械分档：1300W 以上的 ATX 3.1 电源现实中基本都是旗舰产品，
> 硬分会退化成同一个型号重复三次。若某瓦数段可选型号过少，界面会如实告知。

## 显卡功耗墙推算模型（本工具最需要理解的部分）

"所有 AIC 厂商 × 所有显卡型号"是 23 厂商 × 82 系列 × 22 GPU ≈ **上千个组合**。
其中绝大多数厂商从不公布 TBP。如果全部手写，只会得到上千条**无法核实的臆造数字**。

真实情况是：**功耗墙主要由「系列定位」决定，而不是由具体型号决定**。
同一厂商的入门系列与旗舰系列之间存在稳定且可验证的功耗档位差异
（例：RTX 5090 公版 575W → 主流非公 ~587W → 旗舰非公 ~600W → Halo 800W+）。

因此 `db-aib.js` 分两层：

| 层 | 内容 | 置信度 |
|---|---|---|
| **EXPLICIT**（23 条） | 有官方规格或权威实测数据的 SKU，逐条手写并附来源链接 | `official` / `review` / `estimate` |
| **SERIES + build()** | 82 个系列目录，按定位推算其余 SKU 的功耗墙 | 全部 `estimate` |

档位默认倍率（以 RTX 5090 公版 575W 为基准校准）：

| 定位 | powerMult | ocMult | 典型形态 |
|---|---|---|---|
| 涡轮 / 工作站向 | ×1.00 | ×1.00 | 267mm / 2 槽 |
| 入门款 | ×1.00 | ×1.05 | 285mm / 2.3 槽 |
| 主流款 | ×1.02 | ×1.09 | 320mm / 3 槽 |
| 旗舰款 | ×1.05 | ×1.13 | 340mm / 3.5 槽 |
| Halo 旗舰 | ×1.20 | ×1.15 | 340mm / 3.5 槽 |

**诚实性保障**（都有对应测试断言）：

- 规则生成的条目一律 `confidence: 'estimate'`，界面上显示"**规则生成**"徽标与推算过程说明
- 规则生成的条目 **`source` 必须为空**——绝不伪造数据来源（系列名称的来源另存于 `seriesSource`）
- 同厂商内功耗墙必须**随定位单调递增**（低定位的最高值 ≤ 高定位的最低值），
  防止出现"主流款比旗舰款功耗还高"这类建模错误
- 有实测数据的型号走 EXPLICIT 层，覆盖规则推算结果

> 这意味着：**下拉列表里每个型号都可用，但"精确到 1W"的只有标 `official` / `review` 的那些。**
> 规则生成条目的用途是电源容量估算，不是给超频玩家做功耗墙参考。

### 一个真实的纠错案例：微星闪电

初版实现时我把「微星 RTX 5090 Lightning Z」按经验写成了 `700W / OC 800W / 风冷`。
核实 MSI 官方发布信息后发现**三项全错**：

| 项目 | 初版（错） | 实际（MSI 官方，CES 2026 发布） |
|---|---|---|
| 功耗墙 | 700W / OC 800W | **默认 800W，开启"极致"预设可解锁至 1000W** |
| 散热形态 | 风冷 | **标配 360mm 一体式水冷** |
| 厂商建议电源 | 1200W | **1600W** |
| 供电 | 双 12V-2x6 ✅ | 双 16-pin 12V-2x6（理论供电 1200W） |
| 其他 | — | 40 相 VRM，全球限量 1300 张 |

这说明**经验倍率不能替代核实**——Halo 级产品的离散度远超普通非公版。
修正后本工具对该配置的推荐瓦数与微星官方建议完全吻合（1600W），
并已把这条写成测试断言，防止以后回归。

**这也是为什么本工具坚持给每个数据标置信度与来源**：你能一眼看出哪些数字可以依赖。

## 兼容性校验

| 校验项 | 级别 |
|---|---|
| CPU 插槽 ↔ 主板插槽（含 LGA1954 与 LGA1851 不兼容提示） | 错误 |
| **内存类型 ↔ 主板（DDR4 内存插 DDR5 板，物理无法插入）** | 错误 |
| 机箱板型支持 ↔ 主板板型 | 错误 |
| 显卡长度 ↔ 机箱限长（余量 <15mm 时降为警告） | 错误 / 警告 |
| **水冷显卡 ↔ 机箱冷排位（闪电 / 骇客 / 冰龙水冷等）** | 错误 / 提示 |
| M.2 插槽数 ↔ NVMe 数量 | 错误 |
| Gen5 SSD 数量 ↔ 主板 Gen5 M.2 插槽数 | 警告 |
| 内存条数 ↔ 插槽数、总容量 ↔ 主板上限 | 错误 |
| 内存频率 ↔ 主板 / CPU 官方支持值 | 警告 / 提示 |
| 散热器扣具 ↔ CPU 插槽 | 错误 |
| 散热器规格 ↔ CPU 功耗（高 TDP 配小冷排） | 警告 |
| 机箱电源规格 ↔ 电源规格（如 ITX 机箱只吃 SFX） | 错误 |
| 电源 12V-2x6 / PCIe 8pin 接口数 ↔ 显卡需求 | 错误 / 警告 |
| 电源是否 ATX 3.1（配 50 系 / 9000 系时） | 警告 |
| CPU 8pin 接口数（高功耗 CPU 建议 2 个） | 警告 |
| **锁频 CPU + 超频开关（按 MTP 计算并说明超频不生效）** | 提示 |
| **失效的 AIC 板型 ID（数据库升级后旧配置残留）→ 回退公版功耗** | 警告 |
| **推荐瓦数超出 2000W 消费级上限 → 约束到 2000W 并说明缺口** | 警告 |
| 显卡厚度 ≥3.5 槽遮挡 PCIe 插槽 | 提示 |
| 显卡 PCIe 5.0 ↔ 主板 PCIe 4.0（降速 1-3%） | 提示 |

不兼容时给出**具体替代方案**（如列出所有匹配该 CPU 插槽的主板型号）。

## 关于"显卡精确到主板型号 + AIC 厂商"

需求原文要求"显卡选择需精确到具体主板型号与 AIC 厂商"，这里做一个澄清：

- 显卡的**板型 / PCB**（ROG Astral、SUPRIM、AORUS MASTER、Red Devil、闪电…）确实决定功耗——
  同一颗 RTX 5090，FE 版 575W，多数非公 OC 版 600W，Halo 型号 800-1000W。**这部分已完整建模。**
- 而 **Z790 / Z890 / B850 是系统主板芯片组**，不决定显卡功耗。需求里"RTX 5090 + 微星 MEG Z890 ACE"
  混用了两类部件。工具因此拆成两处：
  1. 第 3 步选**显卡板型**（管功耗与供电接口）
  2. 第 4 步选**系统主板**（管 CPU 插槽、内存类型、M.2 数量、PCIe 代数）

两者都参与校验，并额外输出"显卡 × 主板"的实用提示（如 3.8 槽显卡会遮挡下方 PCIe 插槽）。

## 如何扩充数据库

### 新增 CPU（`js/db-cpus.js`）

按 `block()` 的列顺序追加一行即可，`brand / family / socket / memMax` 由 block 配置统一提供：

```js
// [id, 名称, 别名, 核心, PBP, MTP/PPT, ocPeak, 核显, 上市, 参考价, 是否可超频, 备注, 置信度覆盖(可选)]
['cu9-290k', 'Core Ultra 9 290K', '290K', '24C/24T', 125, 250, 250, true, '2026-10', 4999, false,
 '非 K 型号，倍频锁定，PL2 即为功耗上限。'],
```

- ⚠️ **锁频型号（第 11 列为 `false`）的 `ocPeak` 必须等于 MTP**，否则会被测试拦下。
- 第 13 列可覆盖 block 级置信度。典型用法：TDP 是官方值但 PPT 来自爆料时，
  整条记为 `'review'` 比 `'official'` 更诚实（9950X3D2 就是这么处理的）。

### 新增 AIC 系列（`js/db-aib.js`）

```js
{ id: 'brand-series', vendor: '厂商中文名 ENG', series: 'English Series', cn: '中文名',
  brands: ['NVIDIA'],        // 该系列做哪些 GPU 品牌
  tier: 'flagship',          // blower|value|mainstream|flagship|halo
  minTbp: 250,               // 最低覆盖到多大 TBP 的 GPU（Halo 系列通常只做最顶级型号）
  liquid: false, radiator: 0,
  powerMult: 1.05, ocMult: 1.13, bias: 'aggressive',
  length: 340, slots: 3.5,
  source: 'someSourceKey',   // 可选：系列名称本身的来源（与功耗墙来源分开）
  connector: '3× 8pin' }     // 可选，缺省继承 GPU 的公版接口
```

新增后会被自动组合到所有匹配的 GPU 上。**注意同厂商内 `powerMult` 必须随 tier 单调递增**，测试会校验。

⚠️ **注意区域命名差异**：同一品牌在不同市场可能用完全不同的系列名
（耕升：全球 Phantom/Ghost/Python，中国区 炫光/踏雪/追风）。录入前先确认面向哪个市场。

### 新增有确切数据的 SKU（`js/db-aib.js` 的 `EXPLICIT`）

只有查到官方规格或权威评测实测值时才写这里，它会覆盖规则推算结果：

```js
{ id: 'msi-lightning-z-5090', gpuId: 'rtx5090', vendor: '微星 MSI', series: 'Lightning Z',
  cn: '闪电', sku: 'RTX 5090 32G LIGHTNING Z', tier: 'halo',
  tbp: 800, ocLimit: 1000, ocBias: 'aggressive', connector: '2× 12V-2x6',
  length: 300, slots: 2.5, recPsu: 1600, liquid: true, radiator: 360,
  confidence: 'official', source: 'ithome5090lightning', note: '...' }
```

新增来源时在 `js/db.js` 的 `SOURCES` 里加一条，**测试会校验所有 `source` 引用是否有效**。

### 方式二：页面底部「提交新硬件」

填写型号与功耗 → 加入待提交列表 → 复制为 JSON。数据存在浏览器 localStorage，
可发给维护者合并，或自行粘贴进 db 文件。

> 本工具是纯静态页面，没有后端，**无法自动写库**。需求中提到的"定期同步评测网站数据"
> 需要配套抓取脚本与后端服务；当前提供的是**可校验、可追溯、可手动扩充**的数据层。

## 测试

```
node tools/baseline.mjs       # 计算层回归：11 组夹具的数字逐位不变（改版必跑）
node tools/baseline-diff.mjs  # 重抓基线前先跑：把差异分成「计算值」与「建议文案」两类
node tools/build-logo.mjs     # 改标志时跑：从官方 logo 图重提取之眼 + 重建 favicon 与 404
node tools/selftest.mjs       # 189 项  引擎逻辑
node tools/browsertest.mjs    # 144 项 + 单文件 11 + 部署检查 + 窄屏 + 对比度 + 布局 + 声明弹窗 13 + 标志与样式表 7
node tools/dataaudit.mjs      # 数据库自洽性审计（含世代元数据与老卡存量）
node tools/designcheck.mjs    # 设计铁律自检
```

> **标志是生成物，不要手改。** `assets/rog-eye.png`、`assets/rog-wordmark.png`、`favicon.svg`
> 与 `404.html` 里的 data URI 都由 `tools/build-logo.mjs` 从官方 logo 图生成。
> 改标志请改源图后重跑该脚本：它按**元素身份**（`class="eye"` / `class="wordmark"` / `rel="icon"`）
> 定位并重填 404，所以无论 404 当前是模板态、已填充态还是坏的，跑一次都能收敛到正确结果；
> 跑完还会自检「src 是不是完整 data URI、能不能解出合法 PNG」——
> 这一步是必要的，因为把裸 base64 塞进 `src` 时浏览器**不报错**，只显示 alt 文字。

**改版的硬门槛是 `baseline.mjs`**：它冻结了 11 组配置的全部计算输出（逐项功耗、
推荐瓦数、issues 代码、升级建议…）。任何改版只要动了计算层，它就会逐条报出差异。
「我没改计算」不能靠嘴说，得能证明。

> ⚠️ **数据库扩容会合法地改变基线里的一条建议**：`upgradeMaxGpu` 是「按数据挑出来的显卡名」，
> 不是计算值。补了老卡之后它本来就可能换一个答案。
> 所以重抓基线**之前必须先跑 `baseline-diff.mjs`**，它会明确告诉你差异落在哪一类：
> `[数字]` 出现任何一条就是计算层真的被改了（退出码 2，不许重抓）；
> `[文案]` 才允许重抓，并在 `test/baseline.json` 的 `_revisionNote` 里写清原因。
> 2026-09-13 这一轮扩容就是这样处理的：**计算值差异 0**，唯一变化的是
> 「老平台 DDR4」那组的升级建议（Arc A770 → RTX 4070 SUPER，原因见上一节）。

两个脚本分工不同：

| 脚本 | 验证什么 | 是否依赖具体型号的预期值 |
|---|---|---|
| `selftest.mjs` | **计算逻辑**是否正确（功耗累计、电源推荐、兼容性判定） | 部分依赖（用于锁死关键事实） |
| `browsertest.mjs` | **页面交互 + 可发布性**（渲染、联动、导出、无 JS 异常、单文件可独立运行、部署文件齐全、窄屏不溢出、对比度达标） | 不依赖 |
| `dataaudit.mjs` | **数据本身**是否自洽（字段完整性、逻辑关系、覆盖率） | **完全不依赖** |

`browsertest.mjs` 分六段跑：交互测试 → 单文件产物隔离冒烟 → 部署就绪性 → 窄屏与对比度 →
**数据声明弹窗专项** → **品牌标志与样式表完整性**。
弹窗那一段**故意不带** `?nodisclaimer=1`（其余各段都带），因为弹窗本来就该在打开页面时出现。
其中几段用了不显然但必要的手段：

- **窄屏检查用 iframe 而非 `--window-size`**：无头 Edge 有约 504px 的最小布局视口，
  传 `--window-size=390` 只会把截图裁成 390px 宽、布局视口仍是 504px，
  根本测不出移动端问题。改为把页面塞进 390px 宽的 iframe（媒体查询按 iframe 宽度生效），
  并加 `--allow-file-access-from-files` 才能读它的 `contentDocument`。
- **对比度测量期间临时禁用 CSS 过渡**：按钮上有 `transition: all .18s`，
  切换主题后立即读颜色会读到过渡中间值，造成假失败。
- **DOM dump 按 `/\r?\n/` 切分**：Windows 上是 CRLF，按 `\n` 切会在行尾残留 `\r`，
  让 `'flex\r' !== 'flex'` 这类比较莫名失败。
- **`<optgroup>` 的分组名要读 `.label`**：它是属性，不在 `textContent` 里。
  世代下拉的「已停产 · 二手常见」是靠 optgroup label 表达的，用 `textContent` 会误判为「无」。
- **每次运行独立 profile 目录**：无头 Edge 默认复用同一个 profile，
  上一轮的 localStorage 会泄漏到下一轮（表现为「首访竟然已经选好了硬件」）。
- **样式表完整性必须显式断言**：改 404 页时踩到一个坑 —— `<style>` 里某条声明让
  CSS 解析器把后面的规则**全吞了**，表现是「标志变成一块红矩形 + 按钮掉回浏览器默认样式」。
  这种失败**不报任何错**，只能靠「后面那条规则到底生效没有」发现。
  所以现在会数解析出来的规则条数，并逐条验证位于样式表尾部的规则仍然生效。

`dataaudit.mjs` 检查的是数据内部关系，所以新增硬件后它能自动发现新引入的矛盾，例如：

- MTP/PPT < PBP/TDP；锁频型号的 `ocPeak` 超过 MTP；不锁频型号的 `ocPeak` 低于 MTP
- AIB 关联了不存在的 GPU；功耗墙低于同型号公版；水冷板型没写冷排尺寸
- 规则生成条目没标记 `estimate`，或伪造了 `source`
- 同厂商内功耗墙未随定位单调递增
- CPU 平台无配套主板 / 主板无可用 CPU / 主板内存类型无对应内存条
- ITX 机箱没有 SFX 电源可用；高端显卡没有能带动它的电源候选
- **CPU / GPU 缺 `gen` / `genLabel` / `year`，或 `gen` 不在 `*_GEN_ORDER` 里** ——
  这类错误会让这颗 CPU / 这块卡在世代下拉里**永远筛不到**，属于静默丢数据，必须报错
- **`gpuGenMeta` 缺 `year`** —— 世代下拉会直接印出「（undefined 年）」
- **已停产 GPU 存量低于 30 款 / 已停产 CPU 低于 20 款** —— 需求明确要求保留老硬件，
  这条守着不让后续维护顺手把老卡删掉
- 已停产型号没有参考价**不再**算数据缺口（它们只在二手市场流通，写一个数字反而是误导）

## 已知限制（请务必了解）

1. **功耗本质是估算**。真实功耗取决于软件负载、BIOS 功耗墙、环境温度、驱动版本。
   本工具适合排除"明显不够用"的电源，不替代厂商官方建议。
2. **规则生成的显卡功耗墙是推算值**，非厂商实测。只有 `official` / `review` 条目有确切来源。
   Halo 级产品离散度极大，务必以厂商规格页为准。
3. **AIC 系列目录的准确性只经过部分核实**（华擎已逐条核实覆盖型号，微星/华硕中文名已核实），
   且**同一品牌在不同市场的命名可能不同**。
4. **瞬时峰值模型是简化的**。ATX 3.1 规范要求电源能承受短时功率偏移（100µs~1ms 级别），
   所以推荐瓦数按**持续功耗**计算。杂牌电源的标称瓦数往往覆盖不了尖峰。
5. **价格是参考价**，非实时。需求中的"实时价格联动"需要接入电商 API，当前未实现。
6. **未发布硬件的规格会变**。RTX 50 SUPER 的 TGP 来自海韵计算器录入值，NVIDIA 从未确认。
7. **主板自身功耗（12-32W）是按级别估算的**，厂商几乎不公布该数据，这部分置信度最低。
8. **Intel 全系 PBP/MTP 本轮未能独立核实**（核查环境被 intel.com 403 拦截），
   值来自 Intel ARK 通行数据与历代评测。已核实的只有 200S Plus 的核心数与睿频
   （Intel 官方产品简介 PDF 提取物，与库中数据一致）。
9. 兼容性校验覆盖物理尺寸、插槽、接口数量等**硬约束**，但不涉及 BIOS 版本细节
   （如"B850 需更新到某版本才能点亮 Zen 6"）等软约束。
10. **CPU 覆盖以"当前市面在售 + 近几代"为准**，不含更早的 LGA1151/1150/AM3+ 等平台
    （这些多为整机替换而非升级场景，且电源规范差异大）。
    **但显卡覆盖了 GTX 900 / 10 系、RTX 20 / 30 系、RX 500 / 5000 / 6000 系等已停产型号** ——
    因为沿用旧机升级显卡时，"我现在这块老卡功耗多少"本身就是最常见的问题。
11. **已停产显卡的厂商功耗墙绝大多数是规则推算的**，且旧卡经过多年使用后
    **电容老化、硅脂干涸**会让实际功耗与峰值抖动变大，建议比计算结果再留一档余量。
    这些型号在市面上只能买到二手，成色与保修需自行判断 —— 这一段在声明弹窗里也写明了。
