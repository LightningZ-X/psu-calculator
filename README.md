# 台式机功耗计算器

按所选硬件累计整机功耗、做兼容性校验，并给出该买多大瓦数的 ATX 3.1 电源。

纯 HTML + CSS + JavaScript，无框架、无构建步骤、无外部依赖。双击 `index.html` 就能离线跑。

在线版：<https://lightningz-x.github.io/>

## 计算逻辑

### 单项功耗

| 部件 | 取值 |
|---|---|
| CPU | 默认取最大睿频功耗（Intel MTP / AMD PPT）；解锁功耗墙或填了自定义值时按自定义 |
| 显卡 | 取所选 AIC 板型的 TBP；开超频后取该板型的 OC 功耗墙上限 |
| 主板 | 芯片组 + VRM 转换损耗 + 板载控制器，12–32W |
| 内存 | DDR5 每条 3.2–6.5W，DDR4 每条 2.4–3.2W，带 RGB 更高；乘以条数 |
| 存储 | Gen5 SSD 11W / Gen4 7.5W / SATA 3W / HDD 8W（启动瞬间另加 20–25W） |
| 散热 | 水冷 = 水泵 5–9W + 风扇；风冷 = 1–2 只风扇 |
| 风扇 | 单只 1.68–3.6W（ARGB 型号更高） |
| ARGB | 每通道 3–5W，默认按 4W 算 |

### 三个总量

```
规划功耗 = 各部件功耗上限之和
场景预期 = 规划功耗 × 负载系数
瞬时峰值 = 规划功耗 − 显卡 + 显卡 × 尖峰倍率 + 硬盘启动功耗
```

负载系数：办公 0.75 / 游戏 0.95 / 创作 1.00 / 极限 1.08。

选电源用规划功耗（各部件同时满载现实中几乎不发生，但电源得在最坏情况下扛住）；
想了解真实功耗看场景预期。

### 电源推荐

```
安全下限 = 规划功耗 × 1.30，向上取整到标准瓦数
推荐目标 = 规划功耗 × 冗余系数（1.40~1.50），向上取整
最终推荐 = 安全下限 ~ 推荐目标（相等时只显示一个数）
```

- 冗余系数按场景：办公 1.30 / 游戏 1.40 / 创作 1.50；开超频或带机械硬盘时强制不低于 1.40~1.50
- 同时受显卡厂商建议的整机电源约束（如华硕对 5090 全超频平台建议 1000W，微星对闪电建议 1600W），取较大者
- 标准瓦数序列：450 / 500 / 550 / 650 / 750 / 850 / 1000 / 1200 / 1300 / 1500 / 1600 / 2000
- 需求超过 2000W 时约束到 2000W 并说明缺口，不给出买不到的非标准瓦数

两个地方是刻意的：

1. **给区间而不是一个数**。单点阈值向上取整会跳档，1327W 直接跳到 1500W，既掩盖余量也可能让你多花一两千块；给出区间后 1300W 与 1500W 的取舍交给你判断。
2. **推荐目标容许 1% 欠量，安全下限不允许**。高瓦数段跨度很大（1600 → 2000 差 25%），需求只超出不到 1% 时强行跳档，代价是上千元而安全性没有实质差别——模型的功耗数据本身不确定度就远大于 1%。安全下限是硬底线，不启用容差。

### 候选电源

先按硬条件过滤（瓦数达标、机箱电源规格匹配、12V-2x6 / PCIe 8pin 接口数量足够），
再按角色给三个方案：性价比之选（达标前提下最便宜）、均衡之选（贴近安全下限的型号里认证最高）、旗舰之选（瓦数最高、认证最高）。
没按数据库的「基础 / 均衡 / 旗舰」字段机械分档——1300W 以上的 ATX 3.1 电源现实中基本都是旗舰产品，硬分会退化成同一个型号出现三次。

## 显卡功耗墙是怎么来的

「所有厂商 × 所有型号」是 23 厂商 × 86 系列 × 22 GPU，上千个组合，其中绝大多数厂商从不公布 TBP。
全部手写只会得到上千条无法核实的数字。

实际情况是功耗墙主要由**系列定位**决定，而不是由具体型号决定：同一厂商的入门系列与旗舰系列之间存在稳定且可验证的档位差。
所以 `db-aib.js` 分两层：

- **EXPLICIT**（24 条）：有官方规格或权威实测数据的 SKU，逐条手写并附来源链接
- **SERIES + build()**：86 个系列目录，按定位推算其余板型的功耗墙，全部标 `estimate`

档位倍率以 RTX 5090 公版 575W 为基准校准：

| 定位 | powerMult | ocMult | 典型形态 |
|---|---|---|---|
| 涡轮 / 工作站向 | ×1.00 | ×1.00 | 267mm / 2 槽 |
| 入门款 | ×1.00 | ×1.05 | 285mm / 2.3 槽 |
| 主流款 | ×1.02 | ×1.09 | 320mm / 3 槽 |
| 旗舰款 | ×1.05 | ×1.13 | 340mm / 3.5 槽 |
| Halo 旗舰 | ×1.20 | ×1.15 | 340mm / 3.5 槽 |

几条自我约束，都有对应的测试断言：

- 规则生成的条目一律标 `estimate`，界面上带「规则生成」徽标与推算说明
- 规则生成的条目 `source` 必须为空，不伪造来源（系列名称的来源另存在 `seriesSource`）
- 同厂商内功耗墙必须随定位单调递增，不允许出现主流款比旗舰款还高
- 有实测数据的型号走 EXPLICIT 层，覆盖规则推算结果

也就是说：下拉列表里每个型号都能选，但「精确到 1W」的只有标 `official` / `review` 的那些。
规则生成的条目用来估电源容量是够的，不适合当超频参考。

初版把微星 RTX 5090 Lightning Z 按经验写成 700W / OC 800W / 风冷，核实官方信息后发现三项全错
（实际是默认 800W、极致预设 1000W、标配 360 水冷、厂商建议 1600W）。
Halo 级产品的离散度远超普通非公版，经验倍率替代不了核实。修正后本工具对这套配置的推荐瓦数与微星官方建议一致，
这条已经写成测试断言。

## 兼容性校验

硬约束按错误、警告、提示三级给出，不兼容时会列出具体替代方案。

- **错误**：CPU 插槽 ↔ 主板插槽（含 LGA1954 与 LGA1851 不兼容）、内存类型 ↔ 主板（DDR4 内存插 DDR5 板）、机箱板型 ↔ 主板板型、显卡长度 ↔ 机箱限长、水冷显卡 ↔ 机箱冷排位、M.2 插槽数 ↔ NVMe 数量、内存条数与总容量 ↔ 主板上限、散热器扣具 ↔ CPU 插槽、机箱电源规格 ↔ 电源规格（如 ITX 机箱只吃 SFX）、电源 12V-2x6 与 PCIe 8pin 接口数 ↔ 显卡需求
- **警告**：显卡长度余量不足 15mm、Gen5 SSD 数量 ↔ 主板 Gen5 M.2 插槽数、内存频率 ↔ 主板与 CPU 官方支持值、散热器规格 ↔ CPU 功耗、电源是否 ATX 3.1（配 50 系 / 9000 系时）、CPU 8pin 接口数、数据库升级后失效的 AIC 板型 ID（回退公版功耗）、推荐瓦数超出 2000W 上限
- **提示**：锁频 CPU 配超频开关、显卡厚度 ≥3.5 槽遮挡 PCIe 插槽、显卡 PCIe 5.0 插在 4.0 槽上

不涉及 BIOS 版本这类软约束（例如「B850 要更新到某个版本才能点亮 Zen 6」）。

## 已知限制

1. 功耗本质是估算。真实功耗取决于软件负载、BIOS 功耗墙、环境温度、驱动版本。本工具适合排除明显不够用的电源，不替代厂商建议。
2. 规则生成的显卡功耗墙是推算值，只有 `official` / `review` 条目有确切来源。Halo 级产品离散度极大。
3. AIC 系列目录只经过部分核实，且同一品牌在不同市场的命名可能不同。
4. 瞬时峰值模型是简化的。ATX 3.1 要求电源能承受 100µs~1ms 级别的短时功率偏移，所以推荐瓦数按持续功耗算；杂牌电源的标称瓦数往往覆盖不了尖峰。
5. 价格是参考价，不是实时价。
6. 未发布硬件的规格会变。RTX 50 SUPER 的 TGP 来自海韵计算器录入值，NVIDIA 从未确认。
7. 主板自身功耗（12–32W）按级别估算，厂商几乎不公布这项数据，置信度最低。
8. Intel 全系 PBP / MTP 未能独立核实（核查时 intel.com 返回 403），值来自 Intel ARK 与历代评测。
9. CPU 覆盖以当前在售加近几代为准，不含 LGA1151 / 1150 / AM3+ 等更早平台——那些多是整机替换而不是升级场景。显卡反过来覆盖了 GTX 900 / 10 系、RTX 20 / 30 系、RX 500 / 5000 / 6000 系，因为「我这块老卡功耗多少」本身就是升级时最常见的问题。
10. 已停产显卡的功耗墙绝大多数是推算的，旧卡用了多年之后电容老化与硅脂干涸会让实际功耗抖动更大，建议再留一档余量。这些型号市面上只能买到二手，成色与保修要自己判断。

## 扩充数据

**加 CPU**：编辑 `js/db-cpus.js`，按现有条目补 `id / brand / name / gen / genLabel / year / segment / tdp / mtp / oc / socket`。`gen` 与 `genLabel` 决定它在三级筛选里的位置。

**加 AIC 系列**：编辑 `js/db-aib.js` 的 `SERIES`，补厂商、系列名、定位档位、`since` 起始年份、`gens` 世代白名单与散热形态。其余板型由 `build()` 按档位倍率推算。

**加有确切来源的 SKU**：编辑同文件的 `EXPLICIT`，逐条写型号与来源链接，`confidence` 用 `official` / `review`；它会覆盖规则推算的结果。

**不想改代码**：页面底部「提交新硬件 / 纠错」填好型号点「一键提交到 GitHub」，会打开一个预填好数据的 Issue 页，你确认后提交即可。内容只存在本机，不会自动上传。

改完数据之后跑一遍自检，再按下文重新构建产物。
