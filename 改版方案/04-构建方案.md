## 一、总原则（四条，全文贯穿）

| # | 原则 | 说明 |
| --- | --- | --- |
| 1 | **不引入构建步骤** | 保持 `data/*.js` 由 `<script>` 引入。你的传播优势是「可双击打开、GitHub Pages 直传」，引入 webpack/vite 会让维护成本陡增而收益不明显。 |
| 2 | **增量改造，不重写** | 保留 `engine.js` 计算逻辑与全部 `id`；新增逻辑放独立文件（如 `js/ui.js`、`js/wizard.js`），不改写 `app.js` 主体。 |
| 3 | **先修可信度，再改视觉** | 会审发现空态谎报「全部匹配」、首访静默灌预设、手机上看不到结论——这三条不修，UI 改得再漂亮也不可信。 |
| 4 | **数字逐位不变** | 任何阶段结束后，同一组配置的计算输出必须与改版前**完全一致**。这是硬门槛。 |

### 1.1 空态谎报「全部匹配」+ 推荐 3 款电源

- **改哪里**：`app.js:697`（issues 为空时的输出）、`app.js:584`（`#recoBig` 空态）、`engine.js` 的兼容性检查与 `pickPsus`。
- **怎么改**：未选 CPU/GPU 时，兼容性返回「未知」→ 渲染灰色 `◌` 中性态，**任何情况下不得出现 ✓**；`subtotal <= 0` 时 `pickPsus` 返回 `null`，电源推荐区显示空态引导。
- **验收**：清空 localStorage 打开页面 → 无绿色对勾、无电源卡；hero 显示 `—` 而非 `0 W`。
- **风险**：中。涉及引擎分支，必须在 Phase 0 的 baseline 上验证既有配置输出不变。

### 1.2 首访静默灌入 RTX 5090 旗舰预设

- **改哪里**：`app.js:1093` `if (!restored) applyPresetSilent('flagship')`（`applyPresetSilent` 定义在 `:1187`）。
- **怎么改**：首访渲染**空配置**；把「载入示例（RTX 5090 旗舰配置）」做成首屏显式大按钮。localStorage 有记录时才恢复。
- **验收**：新用户第一眼看到空配置 + 明确的示例入口，而不是别人机器的 1200W。
- **风险**：低。

### 1.3 推荐瓦数在窄屏看不到 + sticky 失效

- **现状**：`ui.js` 的 `setupMobileBar()` 只做了「底部条显示数字」，**没有解决「结果列被 10 张卡推到后面」这个根因**。
- **怎么改**：桌面端加**真吸顶条**（总高 ≤80px，只放「推荐 XXX W」+ 错误计数）；移动端在现有 `#mobileBar` 基础上补「点击上滑展开完整报告」。
- **验收**：任何视口宽度与任意滚动位置，「推荐 XXX W」都可见；改任一控件后 200ms 内能看到数字变化。
- **风险**：中。这是整个改版**最关键的单点改动**。

### 1.4 明细表窄屏被裁切 + 触控目标过小

- **怎么改**：表格套 `overflow-x:auto` 容器；窄屏（<640px）明细表改为「一硬件一张小卡」；按钮 ≥44px 高、删除键 ≥44px 宽、复选框 20×20。
- **验收**：360px 宽下能完整看到瓦数与来源列；全部可点元素 ≥44×44px。
- **风险**：低。

### 1.5 对比度补完 + 浅色主题 `--blue`

- **现状**：`--text-mute` 已提到 `#8b95a6`（好），但浅色主题的 `--blue` 是否重定义需核对。
- **怎么改**：核对 `html[data-theme="light"]` 是否覆盖 `--blue` / `--warn`；不足则补。
- **验收**：两套主题全部文本对比度 ≥4.5:1（大字 ≥3:1），用工具实测。
- **风险**：低。

### 1.6 四处 `example.com` 占位

- **改哪里**：`index.html:16` canonical、`:31` og:url、`:32` og:image、`:39` twitter:image（你已在 `:8-10` 注释里标注了这四处），以及 `sitemap.xml` / `robots.txt`。
- **怎么改**：换成真实域名；顺手删掉无用的 `<meta name="keywords">`，修正 `<meta name="author">`。
- **验收**：微信/飞书分享卡片能抓到图。
- **风险**：无。**需要你提供最终域名**（见 C1）。

### 1.7 补一个可见的 `<h1>`

- **现状**：两个 `<h1>` 分别在 `noscript`（L76）与 `.print-only`（L381），**屏幕上都不显示** → 标题层级直接从 20 个 `<h2>` 开始。

## 四、Phase 2 — 数据层重构与覆盖面扩展（3~5 天）

### 2.1 数据与展示分离

**现状**：`js/db.js`（49KB）里 `SOURCES`、`PLATFORMS`、`GPUS`、`MOTHERBOARDS`、`RAM`、`STORAGE`、`COOLERS`、`FANS`、`CASES`、`PSUS`、`EXTRAS` 与装配逻辑混在一个文件；826 条显卡数据由 `db-aib.js` 的规则生成器在运行时推导。

**改为**：
```
data/
  sources.js      来源表（含 sourceDate 与复核标记）
  platforms.js    插槽/平台路由
  cpus.js         原 db-cpus.js
  gpus.js         公版 GPU
  aib-series.js   原 db-aib.js：厂商系列目录 + 规则生成器
  motherboards.js
  ram.js
  storage.js
  coolers.js
  fans.js
  cases.js
  psus.js
  extras.js
  schema.md       ← 字段语义定义（类型/必填/单位/示例）
```

**关键**：仍然只用 `<script>` 标签按序引入，**不引入构建**。`index.html` 里脚本顺序需相应调整（`db.js` 必须最后）。

**验收**：迁移纯搬运，`node test/compare.mjs` 全绿；`db.js` 行数从 729 降到 <150（只剩装配）。

### 2.2 多维描述数据库（schema 升级）

**原则**：**加字段是为了补「决策依据」，不是为了堆参数。** 每个新字段必须回答一个 DIY 用户真实会问的问题。

| 维度 | 新增/统一字段 | 回答什么问题 | 必填 |
| --- | --- | --- | --- |
| 功耗语义 | `tdp` / `maxTurbo` / `ocPeak` / `transient`（倍率）/ `transientMs`（持续时长） | 「这个瓦数在什么条件下成立」 | `tdp`、`maxTurbo` 必填 |
| 供电要求 | `connector` / `pcie8pin` / `eps8pin` / `recPsu` | 「我的电源接口够不够」 | 显卡、电源必填 |
| 物理约束 | `length` / `slots` / `height` / `radiator` | 「机箱装不装得下」 | 显卡、散热器必填 |
| 上市与价格 | `released` / `price` / `priceCurrency` | 「什么年代的、现在多少钱」 | 选填 |
| **获取渠道（新增）** | `segment`（`mainstream` / `budget` / `legacy` / `used-market`）/ `availability` | 「这是新品还是二手/散片」 | **必填** |
| 数据可信度 | `confidence` / `source` / **`sourceDate`（新增）** / **`verifiedBy`（新增）** | 「这个数字哪来的、什么时候的、谁核过」 | `confidence`、`source` 必填 |
| **决策辅助（新增）** | `goodFor` / `avoidIf` / `caveat` | 「适合谁 / 什么情况别买」 | 选填，缺失时 UI 显示 `--` |
| 平台兼容 | `socket` / `memType` / `formFactor` / `atxVersion` | 「能不能插上」 | 按类别必填 |

**UI 侧配合**：
- 卡内提示文字收进 `ⓘ` tooltip（承接 R4）；
- 选中某个硬件后，**就地显示一句 `goodFor` / `caveat`**，这是「增加描述空间帮助决策」的落点；
- 缺失字段**优雅降级**为 `--`，绝不因缺字段报错。

**风险**：⚠️ **字段一多，录入成本暴涨**。必须严格控制必填项数量（上表必填项已是最小集），选填项缺失不得影响计算。

### 2.3 覆盖面扩展（按你选的「够用就行」）

| 类别 | 当前 | 补什么 | 目标 |
| --- | --- | --- | --- |
| 显卡 | 只有 RTX 50/40 + RX 9000/7000 | **GTX 10/16 系、RTX 20/30 系、RX 500/5000/6000 系、Intel Arc、GT 亮机卡**（二手市场绝对主力） | +60~80 个型号 |
| 电源 | **仅 24 款**，550~1600W | **400~550W 入门段**（当前几乎空白）；航嘉/长城/金河田/爱国者等国产走量型号 | 40~50 款 |
| CPU | 164 款，Intel 10~14 代 + Ultra；AMD AM4/AM5 全系 | T 系列低功耗版；**Xeon E5/E3 洋垃圾单独成组或明确排除** | +30 款 |
| 主板 | 有，未核实条数 | B85 / B250 / B360 / B450 / A320 等老平台 | +20 款 |
| 内存 | 16 条 | **DDR3 平台**（二手办公机大量存在） | +8 条 |
| 存储 | 9 条 | SATA 老 SSD、机械盘容量段 | +10 条 |

**老硬件的诚实标注**：功耗值一律 `confidence: 'estimate'`，并在 `sourceDate` 注明推算依据（同架构同规模均值）。**绝不假装是官方数据。**

**验收**：能完整配出这两套并得到合理推荐——
1. 2018 二手主流：`i5-8400 + GTX 1060 6G + B360 + 8G DDR4 + 450W 电源`
2. 洋垃圾：`E5-2680v4 + X99 + RX 580` —— **若决定不做 Xeon，则必须在界面上明确写出「本工具不含 HEDT / 工作站平台」**，避免用户找不到 CPU 而困惑。

### 2.4 「筛选我的平台」开关

新增 `segment` 驱动的筛选：用户可勾选「只看我这种平台」（新品 / 入门 / 老平台 / 二手），下拉列表据此过滤。**这是让扩展后的数据不把界面撑爆的关键。**

## 五、Phase 3 — 结构改造：向导化 + 汇总 + 收纳（5~8 天，最高风险）

### 3.1 分步向导（承接 R2）

- 左列 10 张卡改为**步骤容器**，同一时刻只显示 1 步；
- 顶部横向步骤条（可跳步、已完成打勾）+ 底部 `上一步 / 下一步 / 跳过`；
- **技术红线**：`app.js` 用 `getElementById` 绑定所有控件，隐藏步骤必须用 CSS（`display:none`），**绝不能从 DOM 移除**，否则事件绑定与计算全部失效；
- 新增 `js/wizard.js` 承载步骤切换逻辑，**不改写 `app.js` 主体**；
- `@media print` 必须强制展开全部步骤（`details { display:block }` 之类），保证导出 PDF 内容与现在等价。

**验收**：1440×900 首屏同时可见「步骤条 + 当前步控件 + 推荐瓦数」；`Alt+←/→` 可切步；Tab 顺序正确；打印预览内容与改版前等价。

### 3.4 可达性补齐（承接 R13）

- 每个 `input` / `select` 补 `id` + `<label for>` 关联（**注意：新增 `for` 属性不影响 `app.js` 的 `getElementById`，安全**）；

- `.toast` 从「99px 胶囊 + 满饱和实底 + 大阴影」改为直角 4px、深底 + 2px 左边框、位移淡入 160ms。

**验收**：键盘 Tab 全程可见焦点；读屏能听到推荐值变化；reduce-motion 生效。

## 六、Phase 4 — 视觉重构：真正的 ROG 奥创风格（4~5 天）

**依据**：《01-设计系统-ROG奥创.md》（从华硕官网真实 UI 截图提取，非凭空想象）。
**方向已定（C4）**：**换成真正的 ROG 红 `#ff0033`**，覆盖现有青色主题。

### ⚠️ 这一阶段要推翻的正是上一轮改版的成果

现有 `style.css`（725 行）是「奥创青 `#00d4ff` + 14px 圆角 + 渐变 + 呼吸动画」，那是一次**换皮但没收敛**的改版。本阶段是**换向 + 收敛**，不是叠加。建议做法：

1. **先提交一次现状态的快照**（保留 725 行 CSS），便于对比与回滚；
2. 然后**按设计系统文档重写 token 段**（`:root` 与浅色主题），而不是在现有 token 上打补丁；
3. 组件样式逐块收敛，每改一块就对照设计系统文档第 4 节的三条铁律自查。

### 落地顺序（从影响最大、风险最低开始）

1. **清 emoji**（P0）：`⚡`（logo）`🧩⚡🔴`（引导三步骤）`⚠️`（`app.js:90`）`⚠`（`app.js:262-263` 拼进 `<option>` 文本）全部换成 16px 单色内联 SVG（`stroke:currentColor; stroke-width:1.75`）。`<option>` 里的 `⚠` 移到字段下方文本。
2. **收敛排版**（P0）：**18 档字号 → 5 档**（11 辅助 / 12 标签 / 13 正文 / 16 卡片标题 / `clamp(40px,6vw,56px)` 结论数字）；字重 → 3 档（400/600/700）；数字统一 `tabular-nums`；**中文禁止进 `.big`**（现在 `#recoBig` 空态是 40px/800 的中文「请先选择硬件」，而 mono 字体栈里没有中文字体）；「W」统一 `.unit`。
3. **切断 34 处 `var(--accent)`**（P0）：收敛到 2 处（推荐瓦数 + 主按钮），其余全部改中性灰阶。
4. **改 token**（核心）：按设计系统文档 → ROG 红 `#ff0033` + 中性近黑 `#121212` + 圆角 `2px`；删掉 `--purple` 与 `--glow`；删除全部装饰性渐变与呼吸动画。
5. **复刻 6 个标志性组件**：双斜杠分区标记、数据行、设置行、模式选择器、`>>` 刻度、关键数值块。
6. **形态分离**：输入区去边框 + 左侧竖线；报告区独立质感。破除「完全同构的卡片雨」。
7. **结果列重排**：`.reco` DOM 提到 `.hero` 之前；三宫格降级为次级指标，或改为**负载轨道**（奥创用轨道表达负载率，比三宫格数字更贴切）。
8. **三条反 AI 感铁律逐条自查**（设计系统文档第 4 节）。

### 必须同时守住

- **浅色主题仍可用**（`#btnTheme` 是既有功能，删掉是功能倒退）；
- **`@media print` 把红色指示条、发光、渐变全部压平为纯色**——`style.css` 的打印段是导出 PDF 的唯一实现，**不可删**（`ui.js` 注释里也强调了这点）；
- **不许用中文斜体**（中文无真斜体，浏览器机械倾斜很脏）；
- **不许用斜切 / `skew` / `clip-path` 按钮**（抗锯齿露馅 + 中文难读）；
- **不许用环形仪表当装饰**（该学的是「用轨道表达负载率」这个表达方式）；
- **红色面积 < 3%**，否则从「AI 味」变成「电竞杂牌味」；
- **不要重做已完成的项**：banner 降级、引导瘦身、卡片折叠、当前卡高亮、说明收纳、移动端结果条**都已做完**，只需适配新视觉。

### 验收

- 设计系统文档三条铁律全部通过；
- `grep` 不到 emoji；`grep -c 'linear-gradient'` 仅剩进度/负载条；`grep -c 'animation'` = 0；
- 全站最大圆角 ≤4px；
- 字号唯一值 ≤5 档，字重 ≤3 档；
- 深色 / 浅色 / 打印三种输出都正常。

## 七、Phase 5 — 引导、文案与反馈闭环（2~3 天）

### 5.1 引导（承接 R4）

- 删掉顶部常驻 banner；首次访问用**一次性提示条**（可关闭，状态存 localStorage），之后只在页脚保留一行「数据为估算 · 依据与局限」；
- 新手引导压缩为「一句话 + 两个按钮」，三步骤改横向三图标 + 短标签；
- 术语表移入全局抽屉。

### 5.2 文案去 AI 腔（承接会审第 5 节）

会审指出的模式：**每段先自我解释再给信息 + 用括号/破折号二次补充 + 对「我可能算错」反复致歉**。逐条改写：
- 「我不会选，先用示例试试」→「载入示例配置」
- 「知道了，收起」→ 关闭图标
- 「关于数据可靠性——请先读这一段」→「数据说明」
- 「决定负载系数与冗余要求」→「决定按几成负载估算」
- 删除「规则引擎，非 AI 模型」
- 空态「在上面选好 CPU 和显卡，这里就会出现结果。」→「尚未选择硬件」

### 5.3 反馈闭环（承接 R7）

当前流程「填表 → 存 localStorage → 自己复制 JSON 发给维护者」**等于零功能**。三条改法：
1. **一键生成预填好的 GitHub Issue 链接**（`https://github.com/LightningZ-MSI/-/issues/new?title=...&body=...`）——这是静态站唯一真正可用的收集通道；
2. **本地即时价值**：提交的硬件立刻写入本人 localStorage，并在下次计算时可被选用（标为「我的自定义硬件」）——让提交**对用户本人立刻有用**；
3. **引导式录入**：表单按类别动态显示字段（选「显卡」才显示 TBP / 接口 / 长度）+ 基本校验（数值范围、必填、重复 id 检测）。

### 5.4 静态资源

- 修正 `canonical` / `og:url` / `og:image` / `twitter:image`；
- 重做 `og-image`：去装饰 glow、删掉量纲混乱的第 4 格、加真实界面截图、把「23 条有来源」而不是「826 个大数」做成主张；
- `favicon.svg` 与 header logo 统一（现在一个是矢量闪电、一个是 emoji ⚡，品牌资产自相矛盾）。
